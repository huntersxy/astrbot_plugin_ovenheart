# 烤箱之心 OvenHeart

一个面向 AstrBot 的人格、语言和对话行为学习插件。借鉴 MaiBot 将身份底稿、表达习惯、情境化学习结果分开的思路，通过真实聊天证据积累习惯，并与 LivingMemory 联动理解长期上下文。

**原生 AstrBot Panel 页面，无额外端口、无前端构建、无新增运行时依赖。**

## 使用

1. 使用 **AstrBot 4.29.1 或以上的 4.x 版本**，配置可用的聊天模型。
2. 将发行 ZIP 上传到 AstrBot 的本地插件安装入口，或将插件目录放入宿主的 `data/plugins/astrbot_plugin_ovenheart`，然后重载插件。
3. 打开 Panel 的插件页面 **人格工坊**，让机器人在已启用的群聊或私聊收到几条普通文字消息。会话会自动出现。
4. 在「学习设置」选择审核或高置信度自动生效，也可指定学习对象与学习模型。
5. 积累到默认 12 条素材后后台学习，或点击「开始学习」。在「学习库」检查来源、修改与批准结果。

详细步骤与限制见 [中文指南](docs/zh/README.md) / [English guide](docs/en/README.md)。

## 学习什么

| 类别 | 学习内容 | 应用方式 |
| --- | --- | --- |
| 人格倾向 | 与身份锚点一致的稳定性格、相处习惯 | 补充现有 AstrBot 人格 |
| 表达方式 | 特定情境中的句式、语气、说话节奏 | 回复时挑选相关习惯 |
| 群聊词汇 | 反复出现、含义明确的本地词汇 | 与当前输入相关时参考 |
| 行为策略 | 共情、澄清、倾听、接玩笑等对话应对 | 在宿主已触发的回复中应用 |

人格底稿可人工编辑，支持按会话暂停学习或暂停应用。新结果默认待审核；切换自动生效后，达到置信度与证据门槛的新结果直接生效，其余仍待审核。已有人工修改、拒绝和停用状态不会被相同候选覆盖。

同一习惯可跨批次累计证据并合并相似候选；词汇在第 2、4、8、16 个独立批次重新核对释义。每条保留最近 32 条证据摘录与累计数量；学习、人格和条目操作有最多 30 个可恢复快照。恢复旧版本后，后来新增的条目保留为停用状态，防止下一批学习立即把它们重新激活。

## 0.2 升级与检索

插件 ID 从 `astrbot_plugin_persona` 改为 `astrbot_plugin_ovenheart`，英文名 **OvenHeart**。先停用旧插件，再安装新版；新数据库为空时会复制旧版数据库，保留原文件。原生 View 仍是「人格工坊」，页内标题改为「烤箱之心」。详见中文指南中的迁移映射。

在学习设置填写 AstrBot 已配置的 **embedding 提供商 ID** 后，真实回复使用语义与文字结合的检索，结合证据积累、新鲜度、明确评价和引用多样性排序。未配置、超时或模型出错时回退文字检索。向量按内容和模型缓存，冷启动每次最多索引 64 条，后续回复逐步补齐。免费预览仅用文字检索。

学习库可标记「更合适 / 不太合适 / 清除评价」，记录引用次数与最近引用；引用只说明习惯进入宿主发送阶段，不保证模型采用、消息送达或用户满意。人工编辑和审核决定锁定，不被后续学习覆盖。

模型返回说明文字、代码围栏或已结束的思考标签时可提取 JSON；结构错误最多自动纠正一次，虚构证据直接拒绝，失败保留素材。已用用户指定的 `cn:deepseek-v4-flash` 经真实 AstrBot OpenAI Provider 验证正常学习和纠正分支，使用的是合成素材，并非真实 QQ 会话。

## 0.4 情境筛选与重排序

新安装默认使用「按当前对话筛选」。先召回最多 24 条习惯，可选经过向量检索与重排序，再由学习模型（留空则当前聊天模型）选出 0–5 条适合本次回复的习惯。模型只能选已有 ID，不能改写条目；允许一条也不选，避免看到相同词就强行使用玩笑或安慰。

这个模式每次有生效习惯的回复最多增加一次聊天模型调用，默认等待 12 秒；向量与重排序共用默认 6 秒的召回预算。筛选失败、超时或繁忙时保留宿主人格与人工底稿，本轮不追加学习条目。原有 `hybrid` / `lexical` 仍可选；已保存的模式不强制迁移。免费预览只做文字排序，与真实筛选可能不同。

已通过 AstrBot 原生提供商实测硅基流动免费 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`。在宿主配置模型和密钥，插件只填写提供商 ID；具体字段见中文指南。合成场景结果与局限见 [选择效果验证](docs/evaluation/README.md)，不据此宣称超越 MaiBot 或真实 QQ 验收通过。

## 0.5 模型提示兼容

如果模型能学习和筛选条目，实际回复却不保持名字或语气，可在「学习设置 → 记忆与表达 → 提示投递方式」选择「系统与临时上下文（兼容模式）」。默认仍仅补充系统提示词。

兼容模式同时附加当前宿主角色资料（按预算截取）和本轮已选习惯，不复制完整系统提示词，不修改用户原文或工具权限。附加资料与习惯共用补充字数上限；原生 Agent 保存历史时剔除这些临时内容。自主参与的最近群聊与回复目标也使用临时标记，避免反复进入历史。第三方运行器是否接受并剔除临时内容，取决于其实现。

已用用户指定接口执行「两批聊天学习 → 条目积累 → 筛选 → 实际回复」合成回放，定位并改善了 system 角色与句式未生效的问题。比较原始输出、限制及复现命令见 [学习到回复验证](docs/evaluation/lifecycle.md)。这不证明真实 QQ 或长期效果已通过验收。

## 与现有插件配合

- **LivingMemory**：可选。已适配所提供的 `2.7.0-beta.3` 接口，运行时检测当前实例，复用其访问控制、会话/用户/全局作用域与人格过滤配置。只在批次学习时检索，避免每次回复重复调用记忆。未安装、未就绪、停用或检索失败时仍可独立学习。
- **QQ 能力增强**：可选。不依赖其内部实现，不替换它的工具和事件处理。默认自主参与只发文字；放行的 QQ 工具仍由宿主与 QQ 增强权限约束。
- **AstrBot**：保留宿主原有提示词，不修改宿主人格、不修改其他插件源码。插件数据按完整会话来源与宿主当前生效人格共同隔离。

LivingMemory 检索可能更新访问时间或触发其原有旧作用域迁移；本插件不向记忆库另行写入人格或用户记忆。

## 自主参与与行为边界

0.3 加入消息驱动的参与决策：在「学习设置 → 自主参与群聊」选择关闭、仅观察或自动参与。默认关闭；观察模式仅记录判断，自动模式可决定回复、等待一次或旁观。群聊输入经过 AstrBot 原生白名单、会话、频率和内容检查；命令、直接唤醒与私聊走原有逻辑。

默认三条新消息、两秒合并等待、90 秒回复冷却、每小时最多 12 次自主参与。新输入会取消过时决策；排队中的请求在发送给模型前重新验证。自动回复需要 AstrBot 本地 Agent 运行器，并绑定原生会话以保留人格和历史。工具默认禁用，可通过精确名称白名单放行；只限制自主回复，不改动直接唤醒的原有工具权限。

原「学习记录」页更名为「学习与参与」，显示参与理由、回复目标、等待与取消原因。关闭应用、暂停会话或修改设置会阻止迟到的参与请求。参与决策全局最多两个并发，单会话最多每 30 秒检查一次（冷却更短时使用该冷却），十分钟内最多保留 30 条内存上下文。

本插件不训练模型权重，也没有复制 MaiBot 全部调度、情绪或记忆子系统。已用真实 cn:deepseek-v4-flash 验证旁观、陪伴回应和等待三种合成场景；真实 QQ 送达、长期效果与 MaiBot 对照仍需验证。

采集队列、批次、素材保留、模型超时和学习并发都有边界。失败批次不消耗素材，后台经过冷却后重试。原始消息默认保留 14 天、每个会话人格最多 300 条，定期清理；条目证据摘录随学习条目与版本快照保留。页面提供清除当前会话原始素材的入口，**该操作不删除条目证据摘录**。

## 开发与验证

```powershell
uv sync --python 3.12
# Install a compatible local host for SDK integration tests:
uv pip install --python .venv/Scripts/python.exe -e ../AstrBot
uv run --no-sync python -m pytest -q
uv run --no-sync ruff format .
uv run --no-sync ruff check .
node --check views/workshop/app.js
node --test tests/test_frontend.mjs
uv run --no-sync python scripts/package.py
```

Linux/macOS 的解释器路径为 `.venv/bin/python`。插件核心语法兼容 Python 3.10+，实际宿主 4.29.1 需要 Python 3.12+。未安装 AstrBot 时 SDK 集成测试会明确跳过，SQLite 与学习校验测试仍可独立运行。

`tests/preview_server.py` 是显式启动的本地验收夹具，使用临时数据库和模拟模型，不随插件启动、不进入发行 ZIP。启动命令见文件说明。文档截图标注演示数据，不能作为真实模型输出证明。
