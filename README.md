# 烤箱之心 OvenHeart

一个面向 AstrBot 的人格、语言和对话行为学习插件。借鉴 MaiBot 将身份底稿、表达习惯、情境化学习结果分开的思路，通过真实聊天证据积累习惯，并与 LivingMemory 联动理解长期上下文。

**原生 AstrBot Panel 页面，无额外端口、无前端构建、无新增运行时依赖。**

0.32.1 补齐单字短回复学习：`嗯`、`好`、`？`、`6` 和纯文字 Unicode 表情不再被两字长度门槛静默丢弃，可保留引用前提并进入语言统计。空白、指令、自身消息、黑名单和指定对象过滤不变，仍须满足原有证据与生效规则；默认提示词要求结合语境，不从短附和直接推出稳定性格或认同全部观点。短回复计入原有批量门槛，每批调用流程不变。

0.32 将机器人自身回复接入临时学习语境，帮助理解群友是在回应什么。普通学习和指定对象学习均可使用，不要求开启自主参与；只接入同会话、同人格原生模型回复的发送阶段文字，标为 `self=true`，不成为素材或证据，避免自我循环强化。沿用五分钟、64 条缓存和每次 16 段语境上限，关闭、清除或变更后阻止迟到回填。原生流式路径没有发送后回调时，不补造自身发言；明确引用的机器人原文也会标记为自身语境。

0.31.1 为学习和自检补齐已有素材的采集时间，自检仅自动关联前后五分钟内的邻近素材，避免把不同时段的相邻行误当成问答；明确引用仍保留，跨时段的独立真实证据仍可支持同一习惯。不新增模型调用或数据留存，时间只作辅助语境，不能用来推断作息、在线状态或真实回复速度。

0.31 在「人格底稿」的免费预览旁加入「生成示例回复」。选择真实来源会话后，按已保存底稿、已生效习惯和当前会话聊天模型生成一条示例，共用真实回复的三种投递组装逻辑。按设置执行检索，可能调用筛选、向量、重排序与聊天模型并产生费用；不调用工具、不发送消息、不读取真实聊天历史，也不写入素材、历史或引用计数。其他插件的注入不在示例范围内，生产回复仍需实际验收。原有「预览生效内容」继续免费。

0.30 将缓存友好布局扩展到学习请求：已有习惯按稳定 ID 放在本批素材前，批次计数和细化阶段移到动态尾部的 `known_trait_stats`，保留全部关联信息。学习与自检格式纠正不再改写开头的任务文字，只在尾部追加纠错说明；原重试次数、预算和证据校验保持不变。不发送额外缓存参数，实际命中仍取决于提供商。

0.29 允许有依据地细化未锁定的人格、表达与行为习惯：模型需明确给出 `merge_id` 和 `refine=true`，经自检确认条件和含义兼容后，才按既有独立批次门槛更新。普通同义改写仍只补证据；人工编辑/审核锁定不自动改写。已生效条目只在自动模式且置信度达标时细化，切回审核模式继续保留原生效内容，不增加自检调用。

0.28.1 修复同一群聊词汇在引号、全角/半角写法变化后只累积证据、却无法细化释义的问题。数据库与提取校验统一使用词名比较规则；仍需明确指向同一词条，并满足既有独立批次、审核和人工锁定规则，不按相似拼写擅自合并。

0.28 让 LivingMemory 检索跟随实际学习批次，避免被队列后面刚收到的无关消息带偏。查询均匀取本批素材片段，仍最多 500 字、每批最多一次检索；用本批发言者的真实来源事件判断权限，用户记忆仅关联同一发言者的素材，自检只收到与候选证据相关的记忆。保留 LivingMemory 原有访问、别名、会话/用户/全局及人格过滤规则。

0.27.1 将自主工具检查延伸到原生按名称查找的时刻：新消息、人格工坊内的底稿变更或当前工具策略变化后，旧请求无法再解析出可执行工具。兼容 `full` 与 `skills_like`，保持宿主原始工具对象和直接唤醒路径不变，不增加模型调用。已经开始的工具操作不属于这项查找拦截的撤销范围。

0.27 为情境筛选补充本会话近期的表达参考：条件同样贴合时，鼓励换一种措辞，减少每轮提供同一句式或口头禅。仅参考十分钟内最近三次进入发送阶段的记录，不跨会话或人格，不把生成但未发送的候选算进去；必要时仍可选回原表达。动态 ID 放在稳定候选之后，不增加模型调用，也不改变词汇释义、行为准则或文字/语义模式的排序。

0.26 将引用关系接入学习和入库自检：分析一句回应时，能同时看到它所引用的原文，更好地区分反问、接梗、安慰与否定。无论是否指定学习对象，都可使用平台提供的引用文字；原文仅作为本会话的短暂语境，不额外成为素材或证据。引用作者受黑名单过滤，作者不明且启用黑名单时也不传入学习；沿用现有条数、时效和请求预算，不增加模型调用。

0.25 新增默认开启的「允许连续接话」：刚回复的成员在 120 秒内继续发言、没有其他成员插话时，允许一次跳过最少新消息与冷却的参与判断，避免普通追问被默认三条门槛和 90 秒冷却卡住。仍由 Planner 决定回应、等待或旁观，继续遵守每小时限额、权限与工具策略。可在「学习设置 → 自主参与群聊」关闭；与「提及时马上回复」独立。

0.24 补齐连续参与中的自己回复上下文：首次直接回复也能供下一轮决策参考，并保留当时回答了谁、哪句话。自己的发言使用独立序号，不计入新消息门槛，发送期间的新输入不会被当成已经处理。自主回复通过宿主逐事件开关先完整生成再走普通发送，以便过期检查、真实引用/@ 和发送后记录生效；宿主分段发送仍可用，直接唤醒保留原流式设置。

0.23.1 让表达与群聊词汇检索跟随实际回应对象：回复较早提问时，以那条原文及其引用为依据；直接回复也能理解平台传入的引用文字。已学本群词义不会因为提问只写“这个是什么意思”而被漏掉，也不会因别人的新话题或 Planner 自己提到某个词就强制注入。复用已有检索调用和 2400 字语境预算。

0.23 补齐自主参与的入站引用上下文：即使原消息已经离开最近消息窗口，只要平台提供了引用原文或文字消息链，决策器与最终回复都能看到。区分引用作者与提问者，仍回复实际提问的消息；引用仅保留在本会话临时上下文中，缓存友好模式不改动系统前缀。平台未提供的原文不额外联网补取。已完成关键路径验证，真实群聊效果留待生产环境验收。

0.22.1 回看并保留 0.22 的回复目标与真实引用/@ 改动，同时补齐执行边界：自主工具黑白名单在原生工具按名查找时也有效，`skills_like` 的纯文字回复不再保留任何被禁用的工具处理器；正文 @ 转换排除同名歧义、较长昵称前缀、邮箱、URL 和代码示例。复现与范围见 [原生执行边界验证](docs/evaluation/runtime-boundaries.md)。

最新[充分学习后的连续对话回放](docs/evaluation/warmed.md)使用同一套 10 批、126 条合成素材；MaiBot 达到 44 条原生合格表达，两个词汇实际完成释义推断。双方在本次 12 轮检查中均通过；这支持这些情境中的接近表现，不是自然度排名或整体超越证明。保留第一轮冷词义结果、真实回复及匿名样本，并明确两边回复准入和接口适配的差别。

0.17 新增「学习库 → 全部会话」：默认汇总所有会话与人格的待审核结果，可按类别、状态或指定会话筛选，每页最多 100 条。编辑与审核按条目所属会话生效。学习设置新增「不学习的用户（QQ 号）」，直接填写 QQ 号即可，支持换行、空格和中英文逗号分隔。黑名单优先于学习对象，排除新采集、历史待学素材和临时学习语境；学习中变更会阻止旧结果入库。已有习惯及证据保留，可在学习库手动停用。 Debug 模式可在学习设置中开启，默认关闭；在 AstrBot INFO 日志搜索 `OvenHeart debug` 查看完整注入、检索、学习、自检与参与规划内容，不输出配置密钥或鉴权头。

0.18 默认所有允许的会话共用人格底稿及人格、表达、行为学习结果，可在学习设置中开启「会话隔离」恢复分别设置与应用；聊天历史、原始素材和参与上下文始终保持来源边界。默认缓存友好投递：稳定人格放在系统前缀，每轮习惯与参与目标放在临时尾部，原生历史不保存临时内容；已有明确的旧投递配置保留，可手动切换。一次真实合成回放中，第二轮接口报告 1,408 / 1,778 输入 token 命中缓存；此结果不是固定命中率或费用承诺。详见 [作用范围与缓存验证](docs/evaluation/sharing-cache.md)。

0.18.1 起，「群聊词汇」始终按来源会话与人格隔离，不受总隔离开关影响。旧共用词条在完整证据明确指向单一来源且无本地冲突时原样迁回，保留 ID、审核决定、累计数和向量；来源混杂、缺失、摘录不完整或存在冲突的词条与证据继续保留在学习库，标为「仅保留」，不自动注入。可在来源会话重新学习并审核。

0.18.2 修复工坊设置与 AstrBot 插件 config 不同步：两处使用同一份宿主配置。升级时将旧工坊保存值迁入宿主一次，保留旧值备份；后续重载以宿主 config 为准。工坊保存立即生效，原生配置页刷新可见；原生配置页保存并重载后，工坊自动刷新未编辑的表单。旧表单提交会检查版本，避免覆盖其他页面的新设置。

0.19 新增「提示词」页签，把插件发给模型的每段提示词都变成可编辑模板：参与决策器、习惯选择器、学习分析器、入库自检器、表达参考基调，以及自主参与追加到回复请求的系统提示与临时上下文。模板用双花括号引用运行时内容（如 `{{persona}}`、`{{recent_messages}}`、`{{candidates}}`），保存后立即生效，可随时恢复出厂默认。模板只改变措辞：权限、工具白名单、冷却与小时配额仍由代码控制，结构化 JSON 载荷也仍由插件追加。

0.20 将「自主回复可用工具」改为 AstrBot 工具目录的搜索、多选列表，支持白名单、黑名单、批量选择、刷新及手动补充；两份名单分别保留。默认空白名单仍只发文字，黑名单模式排除所选工具后使用宿主原本可用的工具，不启用宿主停用工具，不影响直接唤醒。另补齐提示词编辑的过期结果、表单和取消保存检查。

0.20.1 修复自主回复挂错对象：参与决策器现在从最近消息中明确选择要回应的那条，宿主引用或 @ 会在发送前绑定到该消息与发送者，不再因为最新一条来自别人（包括另一个 AI）就回到错误对象。旧版自定义决策提示词未给出目标时，仍以最新非自身消息兜底；越界、指向自己或格式错误的目标会被拒绝。

0.22 让参与决策器同时选择引用与 @：`decoration` 可取 `none`、`quote`、`mention` 或 `quote_mention`，发送前直接插入真实的 `Reply`/`At` 组件，宿主不会再叠一层静态装饰。回复正文被明确禁止写 `@昵称`、全角＠或引用标记；正文里能匹配到当前参与窗口、当前发送者或入站引用消息的 `@昵称` 会转成真正的 @，直接回复也有同样兜底。若 AstrBot 平台设置仍开着「引用回复」或「@回复」，模型选择 `none` 时宿主仍会添加，完全由模型控制需关闭这两项。

## 使用

1. 使用 **AstrBot 4.29.1 或以上的 4.x 版本**，配置可用的聊天模型。
2. 将发行 ZIP 上传到 AstrBot 的本地插件安装入口，或将插件目录放入宿主的 `data/plugins/astrbot_plugin_ovenheart`，然后重载插件。
3. 打开 Panel 的插件页面 **人格工坊**，让机器人在已启用的群聊或私聊收到几条普通文字消息。会话会自动出现。
4. 在「学习设置」选择审核或高置信度自动生效，也可指定学习对象与学习模型。
5. 积累到默认 12 条素材后后台学习，或点击「开始学习」。在「学习库」检查来源、修改与批准结果。

详细步骤与限制见 [中文指南](docs/zh/README.md) / [English guide](docs/en/README.md)。

0.16 将两个独立提取阶段并行执行，再统一自检和提交；后台整批预算调整为 180 秒，以容纳实际观测到的慢自检。任一阶段失败会取消并等待另一阶段结束，保留整批素材。验收脚本新增阶段计时，并修正此前低于宿主默认值的单次请求时限。具体原因、对照与限制见 [学习耗时验证](docs/evaluation/learning-timing.md)。

0.15 加入默认开启、可关闭的学习自检，对照原文核对使用条件、身份边界与词义。未通过的新候选转待审，未通过的更新不改旧条目；失败保留整批素材。Panel 展示具体原因，人工审核可以覆盖模型判断。真实模型诊断、完整核心复核与一次保留的超时记录见 [入库自检验证](docs/evaluation/learning-review.md)。0.15.1 让自检同时核对明确的合并目标，避免有依据的新动作给另一种旧习惯增加支持，并取消目标被人工改动后的过期提交，见 [合并验证](docs/evaluation/consolidation.md)。

0.14 补上词名与原始证据的对应校验，统一引号、大小写与全角形式，避免把其他单词内部的字母当成缩写。当前消息直接命中的生效词汇作为本地事实提供，修复“已经学会，却被表达筛选漏掉后改用通用词义”的问题；筛选超时也保留这一路词义参考。首轮失败、修正后的真实回复与边界见 [词汇联动验证](docs/evaluation/jargon.md)。

0.13 明确人格边界在生成时遵守，避免将内部约束当作自我介绍；同时保留当前请求的范围和详细回答能力。新增固定真实学习条目、选中 ID 和历史的成对回复验证，以及交换 A/B 顺序的模型辅助评审。评审有同模型偏差，不作为独立评分或胜率。结果与剩余问题见 [应用规则对照](docs/evaluation/application.md)。

0.12 修复 LivingMemory 旧版不分会话模式被误加会话过滤的问题。使用真实记忆插件、FAISS、免费 bge-m3 和真实学习模型完成隔离的合成数据联调；检查会话/人格过滤、用户别名、全局池、白名单与停用策略。见 [联动验证与边界](docs/evaluation/memory.md)。

0.11 补充按对象区分的语言节奏学习，并将群内词汇独立分析，修复多类别混合学习时漏掉明确释义的词汇。默认开启全部类别时，后台通常分为表达/行为与词汇两轮，共享 90 秒生成与格式纠正预算；任一轮失败均保留整批素材。回复阶段不增加模型调用。已保留与 MaiBot 实际学习、Planner、筛选和回复模块的本地对照，以及尚未评分的 [匿名回复样本](docs/evaluation/rhythm-review-v0.11.md)。条件、失败样本与限制见 [语言节奏验证](docs/evaluation/rhythm.md)。

0.10 修复指定对象学习时的语境缺失：旁人的邻近发言只在会话与人格隔离的短暂内存中帮助理解“对方为什么这样说”，不进入素材库、证据或待学计数。切换学习对象后，旧队列与正在生成的结果都会重新检查资格；不消耗当前对象之外的旧素材。原生核心与真实模型回放见 [指定对象与学习语境](docs/evaluation/targets.md)。

## 学习什么

| 类别 | 学习内容 | 应用方式 |
| --- | --- | --- |
| 人格倾向 | 与身份锚点一致的稳定性格、相处习惯 | 补充现有 AstrBot 人格 |
| 表达方式 | 特定情境中的句式、语气、说话节奏 | 回复时挑选相关习惯 |
| 群聊词汇 | 反复出现、含义明确的本地词汇 | 仅在来源会话与人格中、与当前输入相关时参考 |
| 行为策略 | 共情、澄清、倾听、接玩笑等对话应对 | 在宿主已触发的回复中应用 |

人格底稿可人工编辑，支持按会话暂停学习或暂停应用。新结果默认待审核；切换自动生效后，达到置信度与证据门槛的新结果直接生效，其余仍待审核。已有人工修改、拒绝和停用状态不会被相同候选覆盖。

同一习惯可跨批次累计证据并合并相似候选；词汇在第 2、4、8、16 个独立批次重新核对释义。每条保留最近 32 条证据摘录与累计数量；学习、人格和条目操作有最多 30 个可恢复快照。恢复旧版本后，后来新增的条目保留为停用状态，防止下一批学习立即把它们重新激活。

0.7 修正长期积累：不再因文字很像就合并，避免把“需要建议”和“不需要建议”混在一起；仅使用精确别名或模型明确指定的同类目标。一次学习中，同一习惯即使出现多个候选，也只增加一个支持批次；去重后的证据仍累计，同批置信度先取均值，再与此前批次合成。新结果的自动生效以最终汇总值为准，人工决定保持有效。已存在的旧计数不会猜测性重算。新四批合成回放见 [学习演变验证](docs/evaluation/evolution.md)。

## 0.2 升级与检索

插件 ID 从 `astrbot_plugin_persona` 改为 `astrbot_plugin_ovenheart`，英文名 **OvenHeart**。先停用旧插件，再安装新版；新数据库为空时会复制旧版数据库，保留原文件。原生 View 仍是「人格工坊」，页内标题改为「烤箱之心」。详见中文指南中的迁移映射。

在学习设置填写 AstrBot 已配置的 **embedding 提供商 ID** 后，真实回复使用语义与文字结合的检索，结合证据积累、新鲜度、明确评价和引用多样性排序。未配置、超时或模型出错时回退文字检索。向量按内容和模型缓存，冷启动每次最多索引 64 条，后续回复逐步补齐。免费预览仅用文字检索。

学习库可标记「更合适 / 不太合适 / 清除评价」，记录引用次数与最近引用；引用只说明习惯进入宿主发送阶段，不保证模型采用、消息送达或用户满意。人工编辑和审核决定锁定，不被后续学习覆盖。

模型返回说明文字、代码围栏或已结束的思考标签时可提取 JSON；结构错误最多自动纠正一次，虚构证据直接拒绝，失败保留素材。已用用户指定的 `cn:deepseek-v4-flash` 经真实 AstrBot OpenAI Provider 验证正常学习和纠正分支，使用的是合成素材，并非真实 QQ 会话。

## 0.4 情境筛选与重排序

新安装默认使用「按当前对话筛选」。先召回最多 24 条习惯，可选经过向量检索与重排序，再由学习模型（留空则当前聊天模型）选出 0–5 条适合本次回复的习惯。模型只能选已有 ID，不能改写条目；允许一条也不选，避免看到相同词就强行使用玩笑或安慰。

这个模式每次有生效习惯的回复最多增加一次聊天模型调用，默认等待 12 秒；向量与重排序共用默认 6 秒的召回预算。筛选失败、超时或繁忙时保留宿主人格与人工底稿，不追加表达、性格与行为习惯；0.14 起，当前原始消息直接命中的生效词汇仍作为本地事实提供，共享原有应用条数与字符预算。原有 `hybrid` / `lexical` 仍可选；已保存的模式不强制迁移。免费预览只做文字排序与直接词汇命中，与真实筛选可能不同。

已通过 AstrBot 原生提供商实测硅基流动免费 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`。在宿主配置模型和密钥，插件只填写提供商 ID；具体字段见中文指南。合成场景结果与局限见 [选择效果验证](docs/evaluation/README.md)，不据此宣称超越 MaiBot 或真实 QQ 验收通过。

0.8 补齐筛选上下文：读取最近原生历史中的普通 user/assistant 文字块，自主参与还使用当前会话决策中的近期群聊，让“继续”“就这样”等短句有上下文可依。不向筛选器转交历史中的工具结果、系统消息、思考块、媒体地址或临时资料，也不改写宿主历史。最近上下文最多 1100 字符，当前输入最多 1000 字符，参与目标最多 240 字符；总查询保持在原有 2400 字符限制内。验证见 [对话上下文验证](docs/evaluation/context.md)。

## 0.5 模型提示兼容

如果模型能学习和筛选条目，实际回复却不保持名字或语气，可在「学习设置 → 记忆与表达 → 提示投递方式」选择「系统与临时上下文（兼容模式）」。默认仍仅补充系统提示词。

兼容模式同时附加当前宿主角色资料（按预算截取）和本轮已选习惯，不复制完整系统提示词，不修改用户原文或工具权限。附加资料与习惯共用补充字数上限；原生 Agent 保存历史时剔除这些临时内容。自主参与的最近群聊与回复目标也使用临时标记，避免反复进入历史。第三方运行器是否接受并剔除临时内容，取决于其实现。

已用用户指定接口执行「两批聊天学习 → 条目积累 → 筛选 → 实际回复」合成回放，定位并改善了 system 角色与句式未生效的问题。比较原始输出、限制及复现命令见 [学习到回复验证](docs/evaluation/lifecycle.md)。这不证明真实 QQ 或长期效果已通过验收。

## 0.9 原生核心本地验收

按当前选择先做本地模拟：在临时目录启动 AstrBot 4.29.1 原生核心，由真实插件管理器加载 OvenHeart，使用全部九个原生阶段、真实会话与权限，以及指定的模型；平台发送出口替换为本地收集器。还通过原生 ASGI 路由验证 Panel 未授权拒绝、已授权状态读取与设置保存、View/bridge/脚本加载和页面令牌的作用域限制，不开放额外端口。

这一验收发现并修复了原生唤醒去掉 `/` 后把 `sid` 误当素材的问题。采集现在同时检查平台原文和管线文本。复现、实际生成与边界见 [原生核心验证](docs/evaluation/native.md)。它覆盖本地链路，不代表 QQ 适配器、长期效果或 MaiBot 整机对照已完成。

还修复了真实权限/人格查询异步完成顺序不同导致整批输入被忽略的问题：迟到的旧消息可以补入上下文，但不会接管较新事件的等待窗口；等待结束后再统计完整消息批次。

## 与现有插件配合

- **LivingMemory**：可选。已适配所提供的 `2.7.0-beta.3` 接口，运行时检测当前实例，复用其访问控制、会话/用户/全局作用域与人格过滤配置。只在批次学习时检索，避免每次回复重复调用记忆。未安装、未就绪、停用或检索失败时仍可独立学习。
- **QQ 能力增强**：可选。不依赖其内部实现，不替换它的工具和事件处理。默认自主参与只发文字；放行的 QQ 工具仍由宿主与 QQ 增强权限约束。
- **AstrBot**：保留宿主原有提示词，不修改宿主人格、不修改其他插件源码。素材、群聊词汇与临时上下文按完整会话来源与宿主人格隔离，其他学习遵循作用范围配置。

LivingMemory 检索可能更新访问时间或触发其原有旧作用域迁移；本插件不向记忆库另行写入人格或用户记忆。

## 自主参与与行为边界

0.3 加入消息驱动的参与决策：在「学习设置 → 自主参与群聊」选择关闭、仅观察或自动参与。默认关闭；观察模式仅记录判断，自动模式可决定回复、等待一次或旁观。群聊输入经过 AstrBot 原生白名单、会话、频率和内容检查；命令、直接唤醒与私聊走原有逻辑。

默认三条新消息、两秒合并等待、90 秒回复冷却、每小时最多 12 次自主参与。同一个平台实例、机器人账号和实际群聊共享冷却与限额，即使 AstrBot 为群成员开启了独立会话。新输入会取消过时决策；排队中的请求在发送给模型前重新验证。自动回复需要 AstrBot 本地 Agent 运行器，并绑定原生会话以保留人格和历史。工具默认禁用，可通过精确名称白名单放行；只限制自主回复，不改动直接唤醒的原有工具权限。

原「学习记录」页更名为「学习与参与」，显示参与理由、回复目标、等待与取消原因。关闭应用、暂停会话或修改设置会阻止迟到的参与请求。参与决策全局最多两个并发，单会话最多每 30 秒检查一次（冷却更短时使用该冷却），十分钟内最多保留 30 条内存上下文。

0.6 修复隔离会话之间重复参与的问题：直接唤醒、命令或新的群内输入可打断旧规划，关闭学习也不影响这一协调。新消息在宿主权限验证通过后才参与打断；同一条消息的重复回调和迟到的旧采集不会取消当前规划。只共享最新事件标记与节奏，不跨会话传递聊天正文、习惯或人格。独立会话模式下，新消息门槛和模型上下文仍按各自会话计算；需要整群自然聊天时应使用宿主的共享群会话。升级保留旧会话限额记录，新的共享群记录从升级后开始累积。调度验证与边界见 [原生调度验证](docs/evaluation/participation.md)。

本插件不训练模型权重，也没有复制 MaiBot 全部调度、情绪或记忆子系统。已用真实 cn:deepseek-v4-flash 验证旁观、陪伴回应和等待三种合成场景，并完成 [MaiBot 原生选择器的本地对照](docs/evaluation/maibot.md)：当前端点存在 system 规则不生效的观察，结果主要反映结构化输出兼容性，不能作为整体人格效果排名。当前按用户选择仅做本地模拟；长期效果和两套学习器到最终回复的完整比较仍待验证。

采集队列、批次、素材保留、模型超时和学习并发都有边界。失败批次不消耗素材，后台经过冷却后重试。原始消息默认保留 14 天、每个会话人格最多 300 条，定期清理；条目证据摘录随学习条目与版本快照保留。页面提供清除当前会话原始素材的入口，**该操作不删除条目证据摘录**。

## 提及时马上回复（0.21）

在人格工坊「学习设置 → 提及时马上回复」启用开关，并逐行填写机器人名字、别名，例如 `小夏`、`夏夏`；也可在 AstrBot 插件配置中设置 `mentioned_bot_reply` 和 `mention_names`。默认关闭、名称列表为空，保存后两处配置同步。
