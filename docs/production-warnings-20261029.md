# 2026-10-29 生产告警修复

线上重复告警涉及三个调用问题：

- 人格合库后的后台反馈队列包含多个原会话，重载后尚未收到消息的会话没有临时身份。此前任务会直接进入处理并报“缺少真实会话身份”。现在只领取已有原会话身份的任务，其余保持 pending，不挤占其他会话的批次。仅将这种发生在读取证据前的历史错误重新入队；权限仍按原会话实时检查。
- SDK 调用人物别名解析时使用了未绑定 Engine 的 SQLModel Session。现在绑定实际人物记忆库，并在停止全部房间任务后关闭该 Engine。
- 合库后的向量池未发布双池清单。SDK 回退时可能保存未加载的池，使 known_hashes 变空，而已提交二进制仍存在。现在核对真实模型指纹、已提交文件大小和当前有效记忆 ID，恢复能够逐一匹配的映射，再发布可读取的双池清单。不同模型、未知 ID 或不完整文件不作猜测恢复。

双池可读不代表所有记忆都有向量。清单明确记录已有向量和缺项；缺项继续使用稀疏检索与已有补齐机制，不额外重生成已有向量，也不改写记忆正文和图片资产。

反馈分类器另有真实的模型超时。保留 45 秒预算及告警，补上阶段、等待上限和保留已有记忆的说明，避免只有空白错误文本。

验证：8 项告警定向检查、7 项现有人格合库与隔离检查通过，Ruff、Python 编译与 diff 检查通过。定向检查使用真实 SQLite、SQLModel、向量存储及 SDK 重载路径；不触发生产 QQ 消息或额外模型请求。生产日志与数据状态仍需在部署后独立核验。
