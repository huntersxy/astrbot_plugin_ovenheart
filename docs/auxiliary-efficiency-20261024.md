# 辅助调用用量优化与学习范围

## 调查依据

2026-10-24 线上调查时，最近一小时有 9 批学习，其中 7 批成功、2 批失败；成功批平均耗时约 130 秒。
35 条已保留回合诊断中有 18 次情境选择、17 次回退，没有命中精确选择缓存的记录。
原生 `provider_stats` 与 Cost Control 主要覆盖主聊天，没有完整记录插件直接发起的辅助调用，不能用它们推断辅助模型的历史 token 总量。

最活跃素材来源每小时约新增 266 条、已有 207 条待处理。因此本次保持学习间隔、批量、证据门槛、独立词汇提取和自检，不统一减慢学习。普通旁观判断从最多每 30 秒放宽为默认 60 秒；直接唤醒和既有续接例外保留。

## 请求结构

- 系统规则只放在 system，不再同时复制进用户 JSON 的 `task`。
  学习阶段的增量要求独立保留为 `stage_instruction`，格式修复沿用同一 system，并仅在 JSON 尾部追加修复信息。
- JSON 去除排版空白。学习先放身份、底稿、原始证据和语境，再放阶段参数与该阶段候选。
  同批两次提取能复用共同证据前缀；候选仍分类、按 ID 排序，不为命中率复制全部知识库，也不承诺跨批相同前缀。
- 规划只省略传输顺序、原始图片引用、可由消息 ID 替代的内部 source，以及空引用/媒体元数据。
  作者、编号、完整窗口正文、引用、媒体描述和可回复标志保留；实际计划与回复继续使用原冻结记录。
- 可编辑系统模板仍正常渲染。模板自身引用动态变量时不擅自重写其语义；其前缀复用程度由实际内容决定。

[DeepSeek 官方前缀缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)说明仅重复前缀可复用，不要求把独立任务硬拼成聊天会话。提供商是否实际命中仍以响应 usage 为准。

## 离线样本

从线上存储读取 50 条真实待学素材、40 条知识参考及 40 条群聊记录，比较同一份输入的序列化结构；未调用模型，未发送消息。
重放未包含运行时召回的记忆和完整语言统计，因此是代表性样本，不是生产请求账单。

## 失败退避和真实统计

情境选择器按模型实例、模型配置、规则和超时设置维护失败状态。连续失败两次后先退避 60 秒，后续失败逐步延长，最多 300 秒；成功后清除。精确输入的有效选择缓存仍优先复用，暂停期间只跳过可选情境习惯，不复用其他语境的结论。

`state.data.auxiliary_usage` 按任务、Provider 和实际响应模型汇总最近 24 个小时桶；数据库保留 30 天。字段包括调用数、成功／错误／取消、usage 报告数、输入缓存／未缓存 token、输出 token、输入字符及耗时。
写盘在后台批量进行，不延迟模型响应。缺少 usage、超时取消或服务端继续执行的请求不估算为零成本；这些调用的真实账单仍可能不可见。统计不保存提示词、原始对话或密钥。

## 学习群黑名单与直接回复

`learning_blocked_groups` 仅限制群聊的学习，接受裸群号或完整 UMO；不会把相同数字的私聊加入黑名单。
采集、调度、手动学习、运行中复核和最终 SQLite 入库均检查它。已存素材保留，移出后可以继续学习，不删除既有习惯或正常聊天记录。

明确 @ 与名字提及在宿主追问捕获、会话锁之前优先处理。仅取消该插件拥有的同群未发送自主任务，防止输入被旧自主 Agent 吞为追问；直接流程期间暂停同群自主判断。其他群、已有直接请求、宿主权限与原生会话锁保持各自生命周期。
