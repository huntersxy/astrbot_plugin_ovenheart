# 按人格统一原生记忆库

旧结构为每会话一个 A_memorix 内核和独立数据库。关闭记忆隔离后，同一问题逐库召回正文/关系与事件证据，最后再合并排序。现在每个人格的通用记忆使用一个内核、一套元数据、关系图与模型向量空间；新写入保留真实会话 ID，历史来源按已有记录保留。`memory_isolation` 只控制当前查询和管理操作的可见范围，不再决定物理文件位置。独立的人物事实与画像存储不属于此次逐会话通用记忆库迁移。

## 迁移和回退

插件初始化、开始接收新操作之前，按 `persona.sqlite3` 的会话目录及数据目录中的 `amemorix/persona_sources.json` 来源台账分组。台账保存迁移时确认的人格归属，后续初始化再次核对；与当前人格归属冲突时停止迁移，不猜测归属。历史人格共享库的键可由 `['ovenheart-global-memory', persona]` 的哈希确定，直接合入对应人格，不要求它在会话表中有独立条目。特殊共享范围 `000000000000000000000000` 继续使用原有独立库。

每个人格的目标目录为 `amemorix/rooms/<人格键>`，人格键是人格标识与固定命名空间的 SHA-256 前 24 位。迁移先取得各原库的 SDK 独占写者锁，在临时目录合并，再执行外键、SQLite 完整性及图片字节校验。校验通过并关闭数据库后，原子发布目录及 `persona_store.json` 完成标记；重复启动直接使用完成的库。失败只清理本次临时目录，原会话库保留。

正文、关系、事件、图片出现、描述、关联、来源引用、修正与删除记录保留原标识和来源。实体与同图资产合并；反馈任务的自增 ID 重编号，相关日志、陈旧标记及回滚快照中的任务引用一起映射，并保存旧 ID 对照表。旧模型向量按模型指纹分别合并，保留历史空间，复用已存向量；关系图和稀疏索引使用 SDK 重建，不调用生成或嵌入模型。

原目录不会自动删除。切换后的新记忆只写入统一库；回退代码不会自动拆库或把新增数据写回原目录，不能用旧库覆盖新库。需要回退时先保留统一库和完成标记，再评估代码兼容与数据归属。

## 会话和权限

共享内核的每次调用单独绑定原会话身份，后台反馈和事件生成按实际来源重新检查模型权限。摘要进度和尝试时间仍按原会话分别保存。开启隔离时，正文、人物参考、事件、图片、Panel 列表、详情、操作和导出都限定为当前会话；共用记录的原文证据也按来源过滤。多个会话共用的实体或正文不能在隔离模式下执行会影响其他会话的全局修改。

外层代码负责迁移、AstrBot 身份、权限、取证、调度和 Panel；向量、稀疏、图、事件与语义包导出仍复用 `core/vendor/maibot/amemorix`。本次没有改动 vendor 或工作区中的 MaiBot、AstrBot、LivingMemory 源码。
