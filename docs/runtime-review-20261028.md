## 截图问题的证据

首次回复把图片中的角色称作用户，用户随后说明“这是claude娘”，机器人接受更正。之后用户再次发送同图，机器人只能描述可见特征，追问角色身份时又表示不知道。

22:16 的两次 `query_image_memory` 均返回 `exact_hash`、相似度 1.0，说明原图保存和精确同图检索有效。结果中的观察记录只有视觉模型生成的外观描述，`related_memories` 为空。只读核对发现，用户的说明仍保存在原始素材中，但没有包含 Claude 的有效记忆段落；该说明发生在相应原图出现约 98 秒后。问题在于说明没有与图片建立关联，不能仅靠升级视觉模型解决。

## 本轮调整

1. 参考 MaiBot 已有的图片证据关联方式，在现有 `remember_memory` 中允许提供 `image_evidence`。验证真实消息、图片序号、原文证据、会话/人格归属和学习权限后，复用 SDK 的图片—段落关联；不新增工具，不把机器人猜测当成人类事实。旧调用方式兼容。
2. 同图查询补充原图出现后 180 秒内仍保留的同一发件人原话，每次出现最多四条、最多取三次历史出现。仅对精确同图执行，明确标为附近语境，不自动认定为图片身份，不追溯批量写入旧记忆。
3. 参考 MaiBot 的描述缓存，在图片查询中优先复用已有同图视觉描述，缺少时才调用描述模型。此处只消除查询路径的重复识图，不声称所有后台描述调用都已合并。
4. 图片描述和规划提示明确区分可见特征、用户说明和角色身份，避免把发件人或机器人人格当成图中角色。
5. 配合 Oven Multi 分段移植，让已由其处理的回复跳过烤箱之心的重复断句，但继续校验回复目标。

参考源码为 MaiBot 的 `src/chat/image_system/image_manager.py`、`src/A_memorix/core/utils/summary_importer.py`、`src/maisaka/memory/image_injector.py`，以及已移植 SDK 的图片关联接口。未修改 MaiBot 或 AstrBot。
