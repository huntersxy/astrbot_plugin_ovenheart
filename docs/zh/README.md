# 烤箱之心人格工坊使用指南

## 相同输入的情境筛选缓存（0.46）

情境模式可在一分钟内复用已完成且验证通过的选择 ID，包括明确不选习惯的空结果。缓存最多 64 项，仅在本进程内保留，命中不延长 60 秒有效期，后续请求会清掉过期项。键由有效习惯作用域、模型实际收到的完整请求（身份、候选/片段、上限、近期表达提示、表达意图、对话及模板）和提供商实例/模型/配置生成摘要。隔离模式的不同作用域不复用；共用模式仍受实际候选、人格与对话输入约束，本地词汇的候选 ID 与作用域不被改写。

缓存保存的是摘要、原生提供商引用与 ID，不另存查询、配置文字或模型原始回答；不会把密钥输出到缓存诊断或日志。来源相同但评分、证据计数等未发送给筛选器的元数据变化时，可复用 ID，同时从当前条目重建结果。候选状态/文字/片段和实际请求不同会重算。提供商无法识别或不能可靠生成指纹时，沿用普通调用；生成后提供商或配置变化不发布旧缓存。无效/失败输出及生成中被取消的请求不缓存，不合并仍在执行的相同请求。

缓存命中先于远程并发限制，因此两个筛选请求都在执行时也可使用完全匹配的已完成结果。没有命中时，原最多两个并发及筛选时限不变。原权限、底稿、人格和条目状态仍重新核对，当前输入词汇命中及最终回复生成继续执行。向量/重排序召回仍先按自身缓存与预算运行，不保证本轮没有其他服务调用。免费预览不借此调用筛选模型，也不把一次命中当作实际采用、平台送达或用户评价。

Debug 的检索结果带 `selector_cache_hit`，界面检索说明也会标记已复用。无新开关或数据库结构变化，重载插件清掉缓存。四项缓存检查及三项原有选择/前缀检查通过；真实服务的 KV 命中、费用与耗时改善仍需生产观测。

## 单独审核原话片段（0.44）

在「学习库 → 条目详情 → 原话片段」勾选「移除此片段」，再点「保存编辑」，或与「批准生效」等原审核动作一并提交。勾选本身不写入数据库，取消勾选即可撤回；离页、切换条目和刷新沿用现有未保存编辑保护。规则、未选片段及证据保持原值。实际改写规则仍会按原逻辑清空全部旧片段，页面已说明两者差别。

移除按精确片段文字和条目所属作用域核对，不按可能变化的数组位置删除。片段已不存在/已变化时，移除与同次状态/文字改动整体撤回，提示刷新，不会部分批准。操作留下原有版本快照，并将此条目标为人工锁定；后续对同一条目的学习补证据时不会把片段加回来。恢复历史版本可恢复原片段。已有向量内容指纹、预热和生成预览检查会识别片段变化，不增加模型调用或新列。

这是对本条表达参考的管理：不会删除原证据、历史快照或聊天记录，不是全局禁词；其他习惯、宿主人格、历史与模型自身仍可能使用相同说法。三项原生 API/SQLite 检查通过；桌面模拟界面已确认勾选、离页保护与保存后保留另一片段，移动端未单独验收。[桌面操作结果](../assets/expression-review-v0.44-desktop.png) 使用演示数据，真实回复效果仍待生产观察。

## 多个指定对象的分组取样（0.43）

0.45 起，同一证据组内优先最近较少被成功处理的指定对象，再以原消息顺序打破初始平局。批次无法一次覆盖全部对象时，先前未被处理的对象会在后续成功批次中前移，而不是每次都输给排在前面的长队列。调度顺序与恢复给模型的采集顺序分别记录，避免“时间较早”在提交时再次夺回优先权。只在成功批次提交的同一事务中推进；失败、取消和重试不推进，成功但没有新习惯仍表示该对象已经被分析。未指定或只指定一人时，取样仍保持 FIFO。

新增的 `learning_sender_state` 只存原生作用域、发送者 ID、处理顺序和更新时间，不存正文，不作为证据/置信度/效果反馈，也不进入模型载荷。旧库自动建空表，不猜测历史处理顺序，不改消息或证据 ID。顺序可跨重启保留，按当前原始素材保留期定期清理；「清除原始素材」同时清除该作用域的调度记录。人格历史恢复不回滚已发生的素材处理顺序，其他会话不共享这些记录，即使人格效果默认共用。

容量限制仍然存在：一批不能保证覆盖所有人，原始素材也仍可能到期或达到数量上限；轮转不会绕过最少证据、学习对象/黑名单或激活规则，不增加模型调用。四项 SQLite 检查及一项原生学习回归通过，确认小批次跨轮覆盖、重启、失败、作用域和清理；真实学习质量待生产观察。

「学习对象」明确填写两人或以上时，后台不再直接截取整个队列最早的前 N 条，而是把每人的待学素材按最早顺序分成 `min_evidence` 大小的组：先考虑所有人的第一组，再考虑第二组，以此类推，同一组内按原消息顺序竞争本批容量。选完后恢复全局时间顺序交给分析器，引用链接与真实证据 ID 不变。例如前面积压了 A 的 40 条、后面有 B 的 4 条，批次 8 条且最少证据 2 条时，可各取 4 条；各自的语言统计仍独立计算。

没有指定对象或只指定一人时仍按最早顺序取样。黑名单在分组前排除，即使同时列为学习对象也不会入选；其他会话与人格不会进入本批。未选中素材保持待学，成功只消耗实际提交的这一批，失败仍按原规则保留。每批数量、触发门槛、审核/生效规则、原始素材保留与数量上限均不变，不增加模型调用或开关。

取样提高的是容量允许时的同批对象覆盖，不保证每人一定产出习惯，也不承诺跨批次的严格轮转。如果「对象数 × 每条最少证据数」大于批次容量，本批无法同时容纳所有人的完整第一组；可增加每批素材数或减少指定对象。话语本身缺少稳定风格或证据时，分析器仍应不输出。四项检查覆盖两种证据组大小、默认/黑名单边界、精确消耗及原生学习统计，使用临时 SQLite 与模拟模型；真实学习质量留待生产验证。

## 相近表达的轻量轮换（0.42）

纯文字、混合及重排序模式现在也使用原有的本会话近期表达记录：最近十分钟内三次进入发送阶段的表达 ID，仅用于在相近候选中适度变化。全会话共用人格时，这份近期记录仍属于当前原生会话，不借用另一群或另一成员隔离会话的曝光记录；编辑后已变化的条目仍按原规则重新判断。

轮换只在最多 24 条现有候选中交换表达位置。未提供过的候选评分须在当前表达分数的 5% 容差内，近零分使用 0.005 的绝对容差；没有重排序时，文字匹配率和余弦分数也各不能低超过 0.05。内容与样例完全相同的不同 ID 不算新表达。人格、行为、词汇不参与交换，当前原文直接命中的词汇仍优先；没有相近替代项或所有表达都已近期提供过，就沿用原顺序。情境模式仍尊重筛选模型的明确选择，原有近期表达提示不变。

这是一项软偏好，不是强制不重复。原相关性分数、条数与注入字数预算保持不变，多个表达都能放下时也可能仍一起提供。轮换在远程重排序之后，近期记录不进入重排序/查询向量的缓存键，已有分数可继续复用；默认缓存友好投递仍把变化放入临时内容。不增加模型调用、随机抽样或配置开关。Debug 检索结果的 `expression_rotation` 和选用原因显示本次优先的表达；进入发送阶段不代表模型实际采用、平台送达或用户认可。四项定向检查通过，真实说法多样性留待生产观察。

## 参与判断中的长期背景（0.41）

开启原有「参考 LivingMemory 长期记忆」后，已通过消息数、冷却、小时额度与权限门槛的参与判断，可以在同一轮 Planner 请求中参考长期背景。查询只取最近六条窗口消息中的人类正文及允许的引用，沿用 500 字查询上限；最多参考 `min(memory_top_k, 3)` 条，每条 300 字。`memory_context.for_sequences` 仅指本次查询关联的真实窗口序号，不证明记忆属于这些成员；默认提示要求尊重当前表达、不套用旧个人事实、不把记忆当机器人经历或必须接话的理由。

习惯召回先执行，记忆检索只使用 `retrieval_timeout` 剩余时间，两者不叠加延长这项预算。未安装、未就绪、关闭联动、失败、超时或预算耗尽时继续按近期消息与习惯判断。没有新的参与模型阶段，但记忆搜索可能调用 LivingMemory 自己配置的嵌入、重排序等服务；一次等待后的第二次判断可再次搜索，并使用新一轮共享预算。复用相同有界查询有利于服务自身缓存，不承诺命中或费用下降。

决策尚未选定回复对象时，触发者的 `livingmemory:user:*` 个人记忆不会读入 Planner，避免后来选择另一位成员时混用个人背景。实际回复继续使用现有目标绑定与 LivingMemory 原生召回。其他作用域严格沿用 LivingMemory 的访问、会话/全局/旧版隔离及人格配置；其全局或未隔离模式仍代表其配置允许的共享范围，不会因为 OvenHeart 默认全会话人格而擅自改写范围。

搜索完成后，适配器再次检查 LivingMemory 是否启用/就绪、会话插件集与允许规则、作用域、人格筛选开关和实例/引擎是否相同；变化则丢弃结果。此检查也保护原有学习记忆查询。参与请求在记忆后继续核对 OvenHeart 的权限、设置、底稿和人格，新的输入仍可取消过期规划。摘录数组仅随本轮请求传递，不直接写学习素材、证据、习惯或参与历史；模型生成的参与理由与目标仍按原规则保存，可能概括这些背景。Debug 的 `planner_memory` 与现有请求日志可查看摘录及状态，错误仅记录类型。

自定义 Planner 模板可用 `{{memory}}`；结构化载荷始终带 `memory_context`，旧模板不覆盖。现有开关同时控制学习与参与阶段的这项参考，不改变最终原生 LivingMemory 插件自己的开关。四项参与场景及原有适配策略检查通过，使用临时库、真实策略模块与模拟引擎；真实参与效果、传输和服务速度留待生产观察。

## 流式回复后的连续对话（0.40）

0.40.1 同时修正普通直接回答的多次发送回调：同一原生事件分多次返回回复、逐次触发发送后钩子时，先前第二段起便无法延续本轮完成位置，导致最后一段后的追问失去提前判断资格。现在在该事件上保留带原生作用域的临时群内标记，仅在没有新输入打断时由后续段延续；一旦被其他输入打断，剩余旧段不能重新认领，也不能消耗新的人类消息。各段仍进入同一有界自身语境，连续接话仍须开启、匹配刚回应的成员并由 Planner 判断；小时配额与其他门槛不变。对于宿主把所有分段一次性汇总后只调用一次钩子的路径，原逻辑继续适用。本轮复现了三段回答的故障，两个直接路径检查及一个原有自主分段检查通过；真实 QQ 分段仍待验收。

AstrBot 直接流式回复跳过发送后钩子，但当前原生 Agent 通常会在适配器消费流后提供 `STREAMING_FINISH` 最终正文。插件在该通知处补接原有记录逻辑：必须已有本插件绑定的原生模型请求作用域、宿主发送操作标记，事件未停止且仍有权限，当前有效人格作用域与请求一致。同一结果对象的重复通知只处理一次。中途流片段、单纯模型生成完成、未发送/未绑定的结果和人格切换不会补记。

完成正文沿用最多 1200 字的参与窗口，记录回应对象，供下一轮 Planner 参考；符合「允许连续接话」条件的同成员追问可跳过原有消息数和冷却门槛，其余权限、小时限额、最低把握及过期取消不变。自主参与关闭时不新增回复，直接回复仍沿用宿主流式设置；自主回复继续完整生成后发送，以便发送前检查和真实引用/@。不会在完成通知中重新装饰或重发已经送出的内容。

同一通知也可补接已有临时学习自身语境，仍须有合格的人类素材锚点，并遵守学习开关、黑名单、底稿、五分钟/64 条缓存和 16 段请求预算。正文标为 `self=true`，不成为原始素材、证据或长期习惯，不新增模型阶段；已有应用计数仍按原生曝光去重。宿主完成通知/发送标记不等于平台确认送达，部分失败、被截断的实际流内容也不从模型输出猜测重建；没有最终通知的适配器、Live 路径或旧宿主仍无法提供这项记录。Debug 的 `streaming_self_context` 表示完成通知进入了桥接，实际保留仍取决于原有条件。本轮七项定向检查使用原生 SDK 和模拟消息，真实 QQ 流式传输留待生产验收。

## 有原文依据的表达片段（0.39）

0.39.1 起，`known_traits` 中的表达条目会附带旧片段文字数组 `examples`，与稳定的 ID、情境、规则和状态一起进入分析器；动态支持计数仍放在后面的独立统计区。自检的 `merge_target.examples` 使用同一份文字对照，即使旧条目没有片段也提供空数组。旧片段不带作者/来源元数据、不算本批证据，新的片段仍须逐字对应本批引用原文。提交自检后的合并时重新核对旧片段文字：其他任务只改了片段、或从空变成有片段，也会取消过期结果并保留素材；仅来源元数据改变不影响只看过文字的判断。不增加模型阶段，已用三项原生模拟检查确认正常补充与两种并发变化。

表达习惯除条件与抽象规则外，可保留最多三段具体说法。已有分析器可输出 `examples: [{"evidence_id": 1, "text": "好家伙"}]`。每段最多 60 字，必须逐字出现在本条候选自己引用的素材前 300 字中，重复片段去重、不增加证据数。引用、邻近闲聊、记忆、自身发言及未引用素材不能冒充来源。格式不合要求走原有修正；捏造原文则报错并保留整批素材。旧输出可以省略片段。

现有入库自检同时核对片段与规则的适用性、个人事实、隐私、身份和工具指令，不增加模型阶段。逐字命中只证明来源，不能自动证明内容适用或安全；关闭自检会省去这层模型判断。自定义提示词保持原文，需要新能力时补充字段说明或恢复默认。

文字、向量、重排序与情境筛选均可参考片段。内容指纹包含片段文字，变化后对应缓存重建。实际注入只传文字，不传作者/来源元数据，并服从原字数预算；放不下片段时优先保留抽象规则。缓存友好模式仍放入本轮临时内容。片段仅展示说法与节奏，不是每次必说的台词、机器人事实或工具权限。

学习库显示片段、来源与时间，0.44 起可勾选片段并随保存或审核移除。批准时情境和内容没改动则保留；实际人工改写会清空旧片段。人工锁定后，后续学习不会替换片段；未锁定条目按原生效模式与置信度门槛补充，最多保留前三段。已生效条目处于人工审核模式时不会追加新的生效说法。学习细化改变规则时清掉旧片段，再考虑本次合格片段。恢复快照会恢复片段，旧快照缺字段则恢复为空。

**保留范围**：片段及来源标识随习惯与版本快照保存，与已有证据摘录相同，不随原始素材到期或「清除原始素材」删除。升级只增列、旧条目为空，不自动挖掘旧证据。黑名单变更沿用已有规则，不自动改写旧习惯/片段，可人工停用或编辑清除。本轮四项定向检查使用临时 SQLite 与模拟提供商；[桌面演示](../assets/expression-examples-v0.39-desktop.png) 已查看，移动端未另行验收，真实风格效果待生产观察。

0.38.1 起，回复召回读取所有符合当前作用域的生效习惯精简记录，学习对照读取所有符合可写合并作用域的条目及其实际状态，不再复用面板详情的最近 1000 条列表。这样，早期生效表达和拒绝/停用决定不会仅因新增条目而失去候选资格。共用学习仍只合并共用非词汇条目，词汇只属于来源会话；共用回复沿用原有跨来源非词汇应用规则。

读取不包含证据正文、学习历史或快照；面板详情仍有原来的条数上限，「全部会话」学习库仍分页。召回扫描的内存和排序成本随合格条目数增长。文档向量每次最多补 64 条、重排序/情境候选池和注入预算不变，单批学习提供给模型的旧习惯仍最多 80 条；旧条目获得候选资格不代表每次一定入选，也不代表冷启动已索引完整库。三项模拟检查覆盖超过 1000 条更新记录后的旧向量命中、旧拒绝合并以及共享/隔离边界。

## 本轮表达意图（0.38）

类似本地 MaiBot 表达选择器的 `expression_intent`，参与 Planner 可单独说明本轮的侧重点 `focus`、回应动作 `reply_act`、情境 `scene`、语气 `tone`、偏好 `prefer` 和避免事项 `avoid`。六个字段均可省略，值只能是最多 80 字的文字，合计最多 240 字；不存在时沿用原来的回复目标，等待、旁观或低置信度回复不会携带表达意图。非法类型、未知字段或超长输出按现有格式错误处理，继续旁观。

实际回复时，表达意图加入同一份有界召回查询，并单独交给情境习惯选择器和最终回复请求。它只是有待核对的表达参考：真实消息、当下明确要求、宿主人格与权限仍优先，不能强迫使用某条习惯或调用工具。召回仍限制为 2400 字，为表达意图保留空间时可能缩短召回中的引用尾部；当前人类目标与引用原文的独立词汇命中输入不变，Planner 提到的词不算人类直接命中。

不增加聊天模型调用，不修改直接唤醒流程，不写入长期习惯、证据或新的数据库字段。已有 Debug 请求/响应及注入日志可看到意图，学习与参与历史仍保存原有回复目标。`cached` 模式将本轮意图放入临时用户内容，保持系统前缀处理方式；不代表提供商一定命中缓存。检索、重排序查询发生变化时正常使用不同缓存键。

「提示词」中的习惯选择器、自主参与系统提示与临时上下文均支持 `{{expression_intent}}`。默认 Planner 已说明输出格式；自定义提示词不会被覆盖，旧格式仍可工作，需要新意图时可在原文加入上述可选对象或恢复默认。字段是文字而非 MaiBot 也接受的列表，未复制其完整调度协议。已完成三项模拟检查，真实语气和适用性留待生产环境观察。

## 生效习惯的向量预热（0.37）

借鉴 MaiBot 落库后维护表达向量索引的流程，插件在学习提交成功、人工批准/编辑条目、恢复快照及启动共用人格后，后台尝试准备一批生效习惯的文档向量。它只把生效条目的情境与内容交给配置好的 embedding 提供商，不读取原始素材或证据正文，不生成查询向量，不调用重排序、聊天筛选器或最终回复模型。

预热使用原有内容指纹和模型/作用空间缓存。全局或当前底稿暂停应用、纯文字模式、未配置向量、没有生效条目时跳过；有原生来源时还检查允许会话、宿主插件集及会话/插件启用状态。只允许一个预热任务，已有检索占用锁或另有预热时跳过；已开始的预热与后续检索仍共用同一锁。文档向量阶段预算为 `min(2, retrieval_timeout)` 秒，一次最多补 64 条，不循环扫完整库，不新增开关。

这是可重建的缓存工作，独立于学习和审核提交。提供商失败、超时或插件卸载不会把已提交的结果改报为失败；未完成部分由真实检索按原规则补齐。一批完成不代表全部条目已经索引，大库、连续编辑或被跳过的任务仍可能在首次检索时建索引。配置好的向量服务可能在真实回复前产生文档调用；不承诺额外调用永远为零、固定计费节省或生产时延改善。

Debug 的 `embedding_warmup` 展示本次尝试状态、活跃条目数、批量上限和耗时，异常只记录类型。引用计数、素材与习惯状态不受预热影响。当前验证使用模拟提供商；实际服务速度与群聊体验留待生产验收。

0.36.1 修正无消息 ID 的来源兜底：此前学习采集按“发送者＋秒级平台时间＋文字”去重，同一秒的两条“嗯”等真实回应可能合成一条。现在为首次缺失 ID 的原生事件记录一个稳定的随机来源标识，在采集、参与中断/规划、发送阶段语境和目标锚点间复用；即使到达时间也相同，不同事件仍可分别保留。同一事件的多钩子处理不重复采集，后续才补上的适配器 ID 不会改变已选的兜底来源。

有平台 ID 的消息继续用真实 ID 去重，来源会话边界和长期证据去重规则不变。来源标识不是可引用的平台消息 ID；记忆锚点仍分别核对当前原生 ID、作者、正文与人格，防止已改绑的事件冒充旧目标。没有原生 ID 时，无法可靠区分不同事件对象中的传输重投与真实重复发言，因此按新的到达事件处理；适配器提供真实 ID 时才能跨对象防重。不新增配置、数据库迁移或模型调用。

## 慢群与重启后的引用前提（0.36）

原始回复可以保留多天，但此前明确引用的前提只有五分钟临时缓存，慢群凑齐一批、手动学习或重启后可能只剩“我先听你说”等回应。0.36 起，平台明确提供的 `Reply` 原文随符合采集规则的那条素材写入插件 SQLite；不主动查询平台历史，也不为旧素材补造缺失引用。旧数据库自动增加字段，原消息 ID、已消费状态与去重关系保留。

**数据保留发生变化**：引用最多 1200 字，与对应素材共用 `retention_days`（默认 14 天）和会话原始素材条数上限。到期、超量淘汰或「清除原始素材」时一起删除。它不是独立素材，不增加待学/证据条数，不写入习惯的证据摘录或版本快照；学习请求仍最多取每段 400 字、总共 16 段语境，保持 `relation=reply_to`、作者与 `for_evidence_ids` 关联。明确引用的自身发言继续标为 `self=true`，不能从中学习机器人自己的措辞或结论。邻近闲聊和发送阶段的自身回复仍只保留在原五分钟临时缓存中。

采集和重新读取时都执行黑名单过滤。引用作者已被拉黑，或启用黑名单时作者不明，不传入学习、旧习惯检索或学习批次的记忆查询；符合条件的人类回应仍可单独学习。拉黑不会物理删除此前已保存的引用原文，需清除对应素材或等待其到期；在黑名单生效期间它不会重新从旧临时副本补入。

允许的引用前提也可帮助旧习惯和 LivingMemory 的原有批次查询理解“这个”等简短回应，继续使用各自已有查询/调用预算，不新增每批记忆调用。素材会话/人格边界、全局词汇隔离、证据和审核规则不变。设置页的保存期限说明已标明包含引用；新版只验证本地 SQLite 与调用链，实际误学率与自然度留待生产观察。

## 学习时找到旧习惯（0.35）

学习器的旧习惯对照现在也使用「习惯检索方式」「向量模型 ID」「重排序模型 ID」现有设置。库变大或原文换种说法时，可召回较早的相关条目，供学习提取和入库自检判断是否合并、强化或细化；不是由相似度直接决定合并。

只检索当前作用空间内的现有条目，保留最近 40 条作为补充，最终按 ID 排序。待审核、已生效、已拒绝和已停用条目的真实状态会传入学习器；内部为了召回临时视为候选不改变数据库状态。拒绝/停用仍作为禁止换说法重新学习的对照，人工锁定、自检和既有合并/生效门槛仍由原流程处理。远程检索后重新读取条目和底稿，避免使用旧副本覆盖人工修改；设置、提示词或底稿改变时停止旧学习并保留素材。

检索查询总计最多 2400 字，为本批每条素材分配片段，长消息保留首尾；不会把提取原文也截成这个查询，完整 `observations`、语言统计和证据条数不变。情境模式在这一步仅用语义/文字召回，由原来的学习与自检模型判断对照关系，不增加聊天习惯筛选调用。纯文字模式不调用向量或重排序；配置相应提供商时，会使用现有 `retrieval_timeout` 预算及缓存，之后才进入原有提取/自检预算。未配置或服务失败时回退文字相关性。

Debug 的 `learning_retrieval` 显示查询、召回模式/回退说明和最终对照 ID，不替换页面上的正式回复检索状态。配置提示已注明这项用途，不新增开关。定向检查验证了旧拒绝条目的可见性和调用链，未证明模型必然正确合并或真实群聊质量提升，仍需审核与生产观察。

## 重复重排序的复用（0.34.1）

向量/重排序模式下，同样的判断可能在等待后重判或重复预览时再次发生。已成功校验的重排序分数现在可在五分钟内复用，最多保存 64 项，访问时调整淘汰顺序；不新增开关。回复、Planner 与模型示例共用这个检索器，免费文字预览仍不调用重排序。

指纹包含有效作用空间、按顺序排列的条目 ID/情境/内容、实际查询及非密钥的提供商模型、端点与已支持的请求选项。更换提供商实例会清空缓存；条目或请求改变、过期后重新计算。共用模式只复用相同实际输入的分数，不携带别的会话文本或局部词汇；原有候选作用域、人工停用和发送前检查继续有效。命中后以本次条目重新组装结果，因此引用数、反馈等元数据不会被旧条目副本冻结。

缓存只保存哈希指纹、时间与 ID 对应的分数，不持久化查询、候选原文或提供商密钥。失败、无效结果和取消不入缓存；更换提供商后，旧请求迟到也不会写入新提供商的缓存。纯本地命中可在远程两路并发已满或召回等待预算已用完时直接使用，未命中仍遵守原有并发与超时限制。不合并尚未完成的并发请求。

检索说明会显示「已复用重排序缓存」或缓存来源说明，Debug 的检索结果带 `rerank_cache_hit`。聊天筛选器与最终回复仍照常调用；这不是聊天模型前缀/KV 缓存，也不改变证据、审核或生效规则。实际节省取决于重复率，本轮只用模拟提供商验证，没有测量生产时延、计费或缓存命中率。

## LivingMemory 跟随实际回复来源（0.34）

安装 OvenHeart 0.34 和配套 LivingMemory 本地适配版 `2.7.0-beta.3+ovenheart.1`，然后重载两个插件。这是本地联动构建，不是 LivingMemory 上游正式发布。无需迁移记忆数据库或新增配置；只有旧版 LivingMemory 时，插件继续可用，但运行时仍按原始事件召回。

自主回答较早成员时，OvenHeart 从最多 128 个原生事件锚点中取得真实目标，核对消息标识、正文、作者、原生会话、有效人格及宿主权限，再调用适配接口。锚点独立于学习功能，关闭学习仍可联动；不根据 QQ 号伪造事件。LivingMemory 再检查同一原生群会话、平台、机器人账号、十分钟时效和双方白名单，使用来源快照处理召回与反思；用户作用域因此按实际目标身份解析，原有别名与人格过滤继续有效。被动采集仍处理真实原始群消息。

来源快照不改触发事件或目标原始事件；回复时间与轮次标识取当前请求，避免继承较早目标的旧轮次。请求已失效、来源被淘汰/缺失、跨会话、过期或无权限时，适配版跳过该次召回与反思，模型仍可依据已有会话上下文回应。检查不撤销已经开始的存储任务，不改变 LivingMemory 既有总结与工具语义，也不代表 QQ 已确认送达。当前消息目标、普通直接唤醒和学习批次记忆联动保持原路径，不额外调用记忆或模型。

Debug 的 `participation_memory_source` 展示实际目标来源及绑定状态；旧版本无接口时会注明需要配套适配版。已有配置/数据仍由各自插件维护。定向验证使用原生事件接口和模拟下游，没有接入真实记忆库或 QQ；生产中的自然度及长期记忆质量仍待验收。

0.33.1 将自主回复的模型主问题绑定到 Planner 实际选择的消息。例如甲先提问、乙后发言触发检查，Planner 决定回答甲时，AstrBot 请求的 `prompt` 使用甲的提问；乙的发言继续作为群聊背景，不再占据主问题。回复最新消息时仍保留完整原文，较早消息使用既有窗口内至多 1200 字的正文，不另行查询平台历史。

最终临时上下文显式包含 `reply_message`：目标发言者、正文、序号及入站引用。目标即使在 Planner 可见范围内、却已离开最后 12 条回复上下文，也能被理解。提示词编辑器可用 `{{reply_message}}`；结构化载荷始终提供该字段，已有模板保留。默认说明区分触发事件发送者与实际回应对象，以免宿主附带的身份提醒造成歧义。`participation_injection` Debug 额外记录当时的请求主问题。

这些补充仍为临时内容，沿用原生会话绑定、历史重载、权限和发送前的真实引用/@；不会在生成前把触发事件伪装成另一个用户。当前 LivingMemory 的运行时召回从原始事件提取查询并解析作用域，仍可能使用触发消息而非较早目标；单独修正请求主问题不会改变它。学习批次的记忆联动继续使用现有批次锚点与权限机制，本轮没有修改 LivingMemory 或新增记忆调用。

## 自主参与时的习惯召回（0.33）

自主参与 Planner 现在也能使用「学习设置」里已有的向量和重排序提供商。原来这一步只按文字匹配和已有排序挑选习惯，换一种说法时可能漏掉已学的行为条件。现在使用最近六条本会话消息及引用组成至多 2400 字的检索语境，先召回候选，再交给 Planner 判断是否参与及如何回应。

选择「文字相关性」时不调用向量或重排序；选择语义或情境模式时使用已配置的相应提供商。情境模式在这里仅执行语义/文字候选召回，不额外调用聊天习惯选择器，适用性由已有 Planner 判断；最终回复阶段仍按原来的情境筛选设置执行。候选不能强制触发接话，权限、最少新消息、输入合并、冷却、小时限额及连续接话规则不变。

这些调用复用原有向量缓存、五分钟查询缓存、提供商并发限制和 `retrieval_timeout` 预算，之后才进入原有 `planner_timeout` 决策预算；启用对应提供商会有相应费用或额外等待。失败或超时沿用文字回退，不新增设置。检索结束重新检查作用域、底稿与配置，过滤期间已停用或改写的习惯；暂停或新输入仍取消旧工作。原文、局部词义和上下文保持原作用域，Planner 召回不增加引用计数，也不替换页面上正式回复的检索状态。

开启 Debug 后，`planner_retrieval` 展示本次模式、回退说明、候选与实际装入的条目 ID。默认 Planner 提示词明确要求先核对情境和参与价值；已有自定义提示词保留，可参考新版默认文字调整。此改动已用模拟提供商检查链路，实际接话效果留待生产验收。

0.32.1 移除学习采集的两字下限，允许非空的单字、语气词、标点和纯文字 Unicode 表情成为人类原始素材。例如“嗯”“好”“？”现在能连同其引用前提进入提取、自检和已有语言节奏统计；普通学习与指定对象学习都适用。机器人自身发言仍只有临时语境身份，空白、指令、黑名单和来源权限保持原有过滤。

短回复也计入已配置的待学数量和批量门槛，可能使自动学习更早启动，但不增加每批模型调用、不降低证据条数或审核/自动生效门槛。默认学习与自检提示词要求结合语境区分附和、倾听、疑问和否定，不把短附和当作全面认同，不因符号重复就确定词义或长期性格。既有自定义模板保留，可参考新版默认文字调整；实际语义判断仍应通过审核与生产对话观察。

## 理解机器人与人类的对话（0.32）

学习器现在能用机器人刚才的发言理解人类的后续回应。例如机器人问“想先吐槽，还是一起想办法”，人类回答“先听我说完”时，学习和自检可获得前提，而不把机器人的问题误学成人类的表达。这项能力对普通学习和指定对象学习都有效，不依赖自主参与开关，不额外调用模型。

只从原生模型回复的发送后回调接入文字，必须有仍有效的本会话/人格人类采集锚点，并与生成请求作用域一致；指令、未采集事件或切换人格的旧结果不会补入。自身文字最多缓存 1200 字，按 `self=true` 仅作为前后各两条中的邻近语境，每次取最多 400 字；与原缓存共用五分钟、每会话 64 条、最多 128 个会话和每请求 16 段的上限。它不写入原始素材、证据、聊天历史或引用计数，也不跨群或人格使用；明确引用的机器人原文同样标为 `self=true`。

自身发言不能提供 evidence_ids，默认学习/自检提示词也禁止从自身措辞、偏好、结论或人类的简单附和中形成循环强化。语义判断仍由模型完成，需要继续审核误学。暂停、黑名单、设置变更、底稿调整、清除素材和缓存过期均沿用现有边界；重复发送回调不会重复记录相同文字。Debug 的 `learning_self_context` 可查看接入的自身文字。

发送阶段记录不等于平台确认送达。0.40 起直接流式路径可由发送标记和宿主完成通知补接；缺少通知时不以生成完成替代发送；自主回复仍使用已有的非流式发送路径。示例预览不读取这类语境，也不向它写入内容。

0.31.1 起，学习提取与入库自检的 `observations` 保留素材原有的 `created`（Unix 秒数、本地采集时间）。自动补给自检的前后各两条邻近素材还须与当前证据相隔不超过五分钟；缺少时间的旧格式不自动推断邻近关系，已经明确关联的引用原文继续保留。时间相近不代表主题相同或存在回复关系，跨时段重复出现的独立真实证据仍可支持稳定习惯；这些约束已加入默认学习/自检提示词。

时间来自已有原始素材，不新增采集、留存、配置或模型调用，仍处在稳定已存习惯之后的动态请求尾部。它不是平台原始发送时间，不能据此学习作息、在线状态、真实回复速度或情绪；旧自定义提示词保留，可参考新版默认说明调整。手动审核和证据计数规则不变。

## 生成示例回复（0.31）

在「人格底稿」右侧输入一句话，点击新增的「生成示例回复」。原有「预览生效内容」继续提供免费文字检索预览，入口不变。模型示例须在顶部选择真实素材来源会话，以确定宿主人格、会话权限及当前聊天模型；使用已保存底稿，未保存的编辑请先保存。

示例沿用当前检索设置和真实回复的 `system` / `dual` / `cached` 投递组装逻辑，可能产生筛选、向量、重排序及聊天模型费用。最终生成只调用一次当前会话聊天模型，不调用工具或发送平台消息；不读取真实聊天历史，不写入素材、聊天历史或引用计数。检索可能补齐已有向量缓存，但不替换页面上的真实回复检索状态。LivingMemory 和其他插件的运行时注入不参与示例，因此它是调校参考，不能代替生产验收。

同时只允许一个模型示例请求；生成阶段最多等待 90 秒，检索仍使用自己的原有预算。相关设置、底稿、提示词、宿主人格、模型或选中习惯变化后丢弃旧结果；切换页面或来源也不会让迟到的结果覆盖当前界面。结果按纯文本展示。Debug 的 `model_preview` 包含示例输入、插件系统/临时补充、实际条目 ID、模型回复与耗时；不输出配置密钥，模型原始异常不会直接回显。

## 习惯的有据细化（0.29）

人格、表达和行为习惯不再只能累积证据而永久保留初版。新证据明确补足适用条件、边界或稳定表达时，模型可在候选中提供 `merge_id` 与布尔值 `refine=true`；普通同义改写不用标记。仍须来自本批真实素材，且入库自检明确通过。自检同时核对旧条目的含义、主体与条件，不允许反转目的、扩大适用范围或改变核心身份。

细化沿用既有的四阶段独立批次门槛（2、4、8、16），一批中的重复候选不能跳多级。只更新未被人工锁定的条目：待审核条目可先细化再等待人工决定；自动生效模式还要求本次候选置信度达标，更新已生效条目时累计置信度也须达标。低置信度提议或切回「先审核后生效」时，不替换旧的生效内容。人工批准、编辑、拒绝和停用保持优先；关闭入库自检时，非词汇习惯仍仅补证据，不自动细化。

不新增模型调用、数据库表或配置开关，更新前继续保留快照。自检输入和审计带有 `refine`，Debug 可查看；已有自定义学习/自检提示词可参考新版默认说明更新，未给出该标记的旧格式保持原行为。词汇仍使用原有的词义细化规则。

0.28.1 将词汇释义细化与提取校验统一为同一套词名比较：平衡引号、嵌套引号和 Unicode 全角/半角形式不会再阻止同一词条在独立批次门槛处更新。例如 `LUX` 与 `ＬＵＸ`、`『好家伙』` 与 `“好家伙”` 可按同一词名比较，但仍须明确合并目标或既有精确别名，不做相似词自动合并。人工编辑/审核锁定、停用/拒绝、会话词义隔离和生效方式保持原规则；升级不批量改写旧数据。

## 按实际批次检索记忆（0.28）

LivingMemory 检索不再使用队列外的“最新一句话”作为查询。选定学习批次后，从本批前后最多八条素材均匀取片段，总查询不超过 500 字；每批仍至多一次检索，返回条数、12 秒超时与每条 700 字摘录上限保持原设置。长期记忆继续只辅助理解，不增加证据或原始素材计数。

插件保留最多 128 个按来源会话/人格与发言者标识关联的真实事件锚点，选择本批实际发言者的事件重新验证访问权限，交给 LivingMemory 原有策略解析作用域和别名。不会伪造事件或借用队列外另一人的身份。若事件已被回复装饰改绑成别的发送者，该锚点不再用于原作者。清除对应会话素材和插件重载会清理这些缓存；没有可用来源事件时跳过记忆，保留真实素材学习。

实际解析结果为用户作用域时，仅用该真实用户在本批中的素材查询，并通过 `for_evidence_ids` 限定记忆关联，不把它移用为另一位发言者的事实。会话、全局及兼容作用域继续遵守 LivingMemory 配置，不扩大检索范围。自检只保留与候选所引证据关联的记忆；旧版不带关联的上下文仍兼容。Debug 的 `learning_memory` 展示真实来源用户、本批 ID、记忆摘录及联动状态，不包含密钥。

0.27.1 自主回复除了在生成前缩小工具名单，还会在原生运行器按名称查找工具时复核本次决策的窗口、群内最新输入、启用状态和当前黑白名单。旧请求被替代，或在工坊暂停/修改其底稿后，不能继续从旧工具集合解析出处理器；请求会停止并丢弃待发送结果。`full` 与 `skills_like` 均适用，工具对象不被复制或修改，直接唤醒继续使用宿主原有流程。Debug 的 `autonomous_tool_cancelled` 记录工具名称及决策/策略是否仍有效，不记录参数。

这项检查发生在工具名称解析时，不撤销已经开始的工具，也不覆盖其他插件在解析之后延迟执行的部分；宿主权限、工具自身检查和发送前校验仍继续生效。

## 近期表达与适度变化（0.27）

默认的「按当前对话筛选」会收到 `recent_expression_ids`：当前原生会话/人格十分钟内最近三次引用记录中，仍生效、尚未修改的表达习惯 ID。只有经过发送阶段的参考才计入；生成或预览不计入。这是表达参考的暴露记录，不代表模型采用了措辞、平台已送达或用户满意。即使人格共用，也不拿另一个会话的引用记录影响这里的变化。

默认提示词要求在两种表达同样适合时考虑变化，避免反复提供同一句式或口头禅；情境与身份仍优先，没有替代项时可选回原表达或不选。词汇、性格与行为准则不放入这项提示，不为变化而改写词义或换掉必要策略。文字和语义排序模式保持原有方式。

这项信息复用现有引用记录，不保存更多聊天文字、不增加模型调用。ID 列表放在筛选请求的候选列表之后，与变化的对话一起处于动态尾部；默认系统提示和候选前缀不因此变化。Debug 的 `retrieval` 包含这组 ID。提示词编辑器可用 `{{recent_expression_ids}}`；把动态变量主动写入自定义系统模板时，该模板本身会随 ID 改变。

## 引用辅助学习（0.26）

学习分析和入库自检现在会结合发言所引用的原文，理解“这句回应是在接谁的话、针对什么条件”。无需额外配置，学习全部成员或只指定部分成员时均生效。使用平台提供的 `Reply.message_str` 或文字消息链，不主动查询旧消息。引用通过 `relation=reply_to` 和 `for_evidence_ids` 关联到本批实际素材，模型须区分引用作者与回应者，不能把引用里的身份、偏好、指令或措辞当作学习对象的表达。

0.26–0.35 的明确引用仅保留在五分钟临时学习缓存中。0.36 起，它改为随对应素材保留，详见本指南开头的保存期限说明；邻近闲聊仍使用每会话 64 条、最多 128 个会话的五分钟缓存。引用每段请求取 400 字，每次学习最多参考 16 段，明确引用优先于邻近推断；自检收到相同关联。引用不增加原始素材或证据条数。

黑名单同时过滤引用作者，启用任何黑名单时排除作者不明的引用；设置变更、会话暂停和清除素材沿用现有语境清理规则。原始发言本身仍按既有学习对象与黑名单筛选。已有自定义学习/自检提示词保留，可参考新版出厂默认更新对引用关系的说明。

## 连续接话（0.25）

在「学习设置 → 自主参与群聊」提供默认开启的「允许连续接话」，对应原生配置 `participation_followup`。刚回复的成员在 120 秒内继续说话，且其间没有其他成员插话时，首次跟进可跳过最少新消息、回复冷却与通常的决策检查间隔，经过原有输入合并等待后进入 Planner；本轮仍只能回应这位成员的新发言。致谢、告别或话题结束时可旁观，信息不全时仍可等待。观察后不会因同一次旧回复反复开放提前判断；机器人又真正进入发送阶段，才可开启下一次连续接话。

本会话/人格的短暂自己回复记录是唯一依据，不跨群或用户隔离会话寻找记录；每小时上限、宿主权限、工具名单、最低把握和过期取消仍有效。关闭开关恢复统一门槛与冷却，并取消尚未发出的连续接话回复。自主参与关闭时不会新增回复，仅观察时只记录判断。0.40 起原生流式完成通知可补接记录；缺少完成通知或发送标记时不启用提前判断。提示词编辑器可引用 `{{is_followup}}`，结构化载荷也始终带有该布尔值。

| 原有普通自主参与 | 开启连续接话后 |
| --- | --- |
| 同一人追问也需达到最少新消息并等冷却 | 符合范围的首次跟进可以提前判断 |
| 固定新消息门槛、冷却与小时限额 | 其他聊天保持原门槛和冷却，所有自主回复仍计入小时限额 |

![连续接话设置，使用本地演示素材](../assets/followup-v0.25.jpg)

0.24 起，自主回复使用 AstrBot 原生逐事件 `enable_streaming=false`，先完整生成，再经过发送前的过期检查与引用/@ 装饰，最后记录回复上下文。原因是流式内容送出后才有完成通知，无法再做发送前的过期拦截与装饰；普通宿主分段发送继续可用，直接唤醒与名称提及回复仍沿用宿主原有的流式设置。

非流式回复在发送阶段将最多 1200 字正文和回应对象写入本会话/人格的临时参与窗口，包括还没有普通群消息窗口时的首次直接回复。自己的发言有独立序号，不能作为模型回复目标，也不满足最少新消息门槛；发送期间新到的用户输入不会被清掉。窗口仍受 30 条、10 分钟和最多 128 个会话的限制，回复不成为学习素材或跨群上下文。发送阶段记录表示内容经过宿主发送流程，不代表平台已确认送达。0.40 起直接流式回复可由已发送标记加原生完成通知补接同一记录；不以单纯模型生成完成替代。

0.23.1 起，表达、行为与词汇检索优先理解本轮实际回应的原文和引用，不再总将最新群聊消息当作问题。已有本群词义可从提问所附的引用中直接命中，情境筛选选择不用表达或失败时也保留；其他群友的新话题、历史或 Planner 自己写出的词不计入这项直接命中。直接唤醒同样支持平台提供的引用文字。查询仍最多 2400 字，先保留回应原文、引用及目标，再使用剩余预算放近期语境；不增加模型调用，词义仍按本会话与人格隔离。

0.23 自主参与能读到消息附带的引用原文：先使用同会话有效窗口中的原消息，否则使用平台传入的 `Reply.message_str` 或文字消息链，最多 1200 字。决策与最终回复均收到 `reply_to`，可理解“这句话”“这个结果”，并区分引用作者和当前提问者；窗口外的引用不会成为额外可选回复目标。仅在临时参与上下文中使用，缓存友好模式继续放在历史之后，不单独写成学习证据或持久历史。若平台只提供引用编号，插件不主动查询消息；模型仍可能需要询问缺失原文。已保存的自定义提示词保持原文，可在提示词编辑器参考新版默认提示词更新。

0.22.1 保留 0.22 的规划引用/@ 功能，并收紧自动转换：只有当前语境中唯一对应用户的完整昵称才转成真实 @，同名成员、较长昵称前缀、邮箱、URL、行内/围栏代码保持原文；兼容全角 `＠`。自主工具在原生调用时也受黑白名单限制，模型猜出隐藏名称不能调用。详见 [执行边界验证](../evaluation/runtime-boundaries.md)。


## 全会话共用、可选隔离与缓存友好投递（0.18）

默认 `session_isolation=false`：人格底稿和新学到的人格、表达、行为习惯进入共用空间，在所有允许的会话中应用。顶部「学习素材来源」只选择待学素材与学习/参与记录，不切换共用底稿。即使没有收到消息，也能先编辑共用底稿。学习仍按真实来源会话分批，引用原文保留来源标签；不会把不同群的原始消息拼成同一批，也不混用临时语境、聊天历史或参与决策。相同平台消息编号会连同来源会话一起去重，跨会话的不同证据可以正常累积。

需要分别设置时，在「学习设置 → 学习范围」开启「启用会话隔离」并保存。此时顶部恢复为「会话与人格」，人格底稿及学习结果按完整会话和 AstrBot 人格分别读写。切换保留共用与独立空间，正在生成的旧批次不能跨模式提交。关闭隔离即可恢复共用底稿和习惯。

升级时，旧的独立底稿保留在原位置，不擅自拼接为一个身份；可开启隔离继续使用。旧的已生效人格、表达与行为习惯在共用模式下也能跨会话参与检索，旧条目的审核状态保留；之后新学习的这三类内容进入共用空间。新学习会与共用空间内的相同条目累积或合并。共用条目在学习库中显示为「全会话共用 / 所有人格」，证据摘录显示真实来源；旧的独立条目仍保留原归属。隔离模式不自动复制共用条目到各会话。

0.18.1 起，「群聊词汇」始终按完整会话与 AstrBot 人格隔离，无论「启用会话隔离」是否勾选。同一个词可以在不同群有不同含义，学习、合并、释义精炼、预览、实际召回与引用统计都遵守此边界。共用批次分别为共用空间和本地词汇保留快照，恢复操作旁标明作用空间。

升级自动迁回完整证据只指向一个有效来源、且没有本地指纹或别名冲突的旧共用词条，保留原 ID、内容、证据、审核状态、评价、计数与向量。其他旧共用词条完整保留在「学习库 → 全部会话 → 群聊词汇 → 全部状态」，显示「仅保留」，不参与回复，也不能直接批准为全局词义；请在相应来源会话重新学习后审核。不会猜测缺失的来源或将混杂释义分发到多个群。

| 旧行为 | 0.18.1 行为 |
| --- | --- |
| 顶部选择会话后总是切换人格底稿 | 默认编辑共用底稿；开启隔离后才切换独立底稿 |
| 默认按会话与人格分别学习和应用 | 默认共用人格、表达与行为；群聊词汇、素材与参与上下文始终隔离 |
| 新安装默认 `guidance_delivery=system` | 新安装默认 `cached`；已保存的 `system`、`dual` 保留，可手动切换 |

## 工坊设置与插件 config 同步（0.18.2）

## 回复目标绑定（0.20.1）

参与决策器从最近消息里选择实际要回应的那条，输出 `target_sequence`，并在回复目标里写清对象。发送前插件把宿主的引用回复和 @ 绑定到这条消息及其发送者，所以「想提醒造物主」这类插话不会因为最新一条是另一个 AI 的回答而挂到它下面。

| 情况 | 实际行为 |
| --- | --- |
| 目标为最近消息之一 | 引用/@ 指向该消息或发送者，回复正文仍由宿主生成 |
| 目标是自己的消息 | 拒绝本次决策，原因写入「学习与参与」 |
| 目标不在窗口内或格式错误 | 拒绝本次决策，原始素材与上下文保留 |
| 旧版自定义提示词未给目标 | 以最新非自身消息兜底，保持升级前行为 |

该绑定只改变宿主发送时的引用/@ 对象，不修改模型生成的正文、不新增 @ 组件、不放宽工具权限。等待与旁观决策不携带目标。0.22 起，是否真正插入引用和 @ 由下面的 `decoration` 决定。

## 引用与 @（0.22）

自主参与的引用和 @ 不再由宿主的固定开关单独决定。参与决策器在 `target_sequence` 之外返回 `decoration`，两者绑定同一条目标消息：

| `decoration` | 发送前插入的组件 |
| --- | --- |
| `none` | 不额外插入；宿主原有引用/@ 设置仍可能生效 |
| `quote` | 消息链首插入真实 `Reply`，引用目标消息 |
| `mention` | 消息链首插入真实 `At`，@ 目标消息的发送者 |
| `quote_mention` | 同时插入 `Reply` 与 `At` |

AstrBot 的结果装饰阶段只会在整条链都是纯文本或图片时补静态引用/@。插件插入真实组件后该条件不成立，宿主不会再加第二层，也不会出现引用指向 A、@ 指向 B 的情况。

回复模型被明确要求不要在正文里写 `@昵称`、全角＠、引用标记或消息编号。发送前仍做一次兜底：正文里能匹配到当前参与窗口、当前发送者或入站引用消息的 `@昵称` 会转换成真正的 `At` 组件；匹配不到的名字不会伪造 @。直接回复也走这条兜底，但它的引用/@ 是否添加仍取决于宿主配置和实际正文。

`none` 的限制：插件没有逐条关闭宿主装饰的公开接口。若 AstrBot 平台设置开启了「引用回复」或「@回复」，模型选择 `none` 时宿主仍会按原设置添加。想要完全由决策模型控制，请关闭这两项。

旧版自定义决策提示词没有 `decoration` 字段时，插件会在请求末尾追加字段要求，不改用户原文；模型仍未输出时保持 0.20.1 的目标绑定和宿主设置，升级不会让旧模板失效。格式错误或未知的 `decoration` 会被拒绝，等待与旁观决策不携带装饰。

## 全部会话与学习黑名单（0.17）

打开「学习库」，会话筛选默认「全部会话」、状态默认「待审核」，直接汇总所有会话与人格的结果。原来需在页面顶部逐个切换会话，现在可在学习库内部切换全部或单个会话；顶部选择仍用于人格底稿、开始学习与历史记录。学习库标签上的数字是全部会话的待审核总数。类别、状态筛选在分页之前执行，每页最多 100 条，可用上一页、下一页遍历全部结果。列表与详情均标明所属会话、人格；编辑、评价、批准、拒绝及停用作用于该条目的所属会话，不改变顶部所选人格。切换筛选、条目或翻页时保留未保存编辑的确认。

在「学习设置 → 学习范围 → 不学习的用户（QQ 号）」直接填 QQ 号，无需平台前缀；多位用户可用换行、空格、中英文逗号或分号分隔。保存后名单去重，重新打开会逐行显示。它是插件全局的学习排除名单，也优先于「只向这些用户学习」。被排除用户的新文字不会进入素材或临时学习语境，已有但未学的素材不进入批次或待学计数；学习途中变更名单会使旧批次保留素材、放弃结果。移出黑名单后，保留的未消费素材可重新参与学习。

已有学习条目和证据不会自动删除或追溯撤销，可在学习库检查并停用。此项只控制本插件的学习来源，不是 QQ 平台封禁，也不改变 LivingMemory 自己的采集规则或宿主回复权限。

## 首次设置

0.11 会从同一对象至少四条有效素材中汇总句长、分段、提问与列举特征，辅助学习情境化的说话节奏。统计不替代原始证据，也不直接规定回复字数；不同对象与旁人语境分开处理。词汇使用独立阶段，避免普通句式挤掉群内明确释义的词。完整启用时通常两轮提取；仅启用词汇或仅启用其他类别时一轮。0.15 默认在有候选时再做一轮自检，可在「学习设置 → 学习与生效」关闭。0.16 将两段提取并行执行，再统一自检；提取、自检及各自最多一次格式纠正共享 180 秒后台预算，失败不提交部分结果或消耗素材。

如果希望日常更接近短句群聊，可在「人格底稿 → 表达基调」写明日常简短、明确要求详细时展开。现有底稿保持不变，插件不会替你强设统一语气。一次 66 条合成素材的对照包含自然闲聊和详细请求；原始检查存在中文数字、欢迎语同义表达等误报，不能把分数当自然度。[验证说明](../evaluation/rhythm.md)。

先在 AstrBot 配置你的核心人格，再在允许的会话中发几条普通文字消息。插件按当前宿主实际生效的人格与完整会话来源分别保存素材，切换人格会看到独立的学习空间。群聊优先显示群名，私聊显示对方名字；群名不可用时显示群号。

建议先保留「先审核后生效」，也可按需要切换为「高置信度自动生效」。这是**配置项**：自动模式适用于新候选与尚未人工决定的待审核条目，不重新激活已拒绝、停用或人工锁定的旧条目。置信度来自模型评估，不是统计保证；默认还要求至少两条不同原始消息作为证据。

「只向这些用户学习」每行一个用户 ID，留空为允许会话中除机器人自身以外的发送者。「允许学习与应用的会话」填写完整 `unified_msg_origin`，可通过 AstrBot `/sid` 获取，留空为所有已启用会话。AstrBot 自身的白名单、插件集、会话与插件开关仍生效。

0.10 在指定学习对象时，短暂参考同一会话、同一人格中旁人的邻近发言，以区分目标是在倾听、接玩笑还是应要求给建议。旁人的文字不会进入本插件的素材库、条目证据或待学计数；模型也不得从中学习。只使用五分钟内、每条目标消息前后最多两条邻近位置的上下文，每次学习最多 16 段、每段 400 字。缓存上限为 128 个学习空间、各 64 条，后台清理过期内容；重启不恢复。修改设置、人格底稿或清除该会话素材会清理对应缓存。

切换对象不会删除原有素材，待学计数只显示当前对象；生成过程中切换对象会取消旧结果并保留素材。之后重新选择原对象，仍可处理未过期的旧素材。邻近文字只是理解情境，不是该目标说过那些话的证据；重启、缓存淘汰或较旧批次可能没有邻近语境，模型必须依现有素材保守判断。[验证记录](../evaluation/targets.md)。

## 批次和模型

默认积累 12 条素材触发自动学习，每批最多 30 条，同一会话的尝试间隔至少 600 秒；全插件同时最多一个学习模型请求。连续失败会按会话退避，间隔从设置值逐次翻倍、最多一小时，下次成功后恢复正常间隔；在调用模型之前就被本地拦截的批次（如学习已暂停、底稿刚被改写）不参与退避，修正设置后立即可以重试。手动学习可绕过自动素材门槛与冷却，但仍需要满足最少证据数。一次模型请求超时为 90 秒；记忆检索超时为 12 秒。

「学习模型 ID」留空时使用该会话当前模型，否则填写 AstrBot 已配置的提供商 ID。插件不会自行设置或保存 API Key。模型应输出指定 JSON。支持从说明文字、单个代码块和已闭合的思考标签之后提取结果；每个阶段的字段结构错误可携带原批次纠正一次，各阶段及其纠正共享 90 秒预算。输出截断、只含思考、反复格式错误会提示原因并保留素材；虚构证据直接拒绝，不进行格式修复。空候选数组是有效结果，代表本批没有足够依据提炼习惯。

学习期间暂停、停用会话或修改底稿，迟到的学习结果不会覆盖新的设置。同一习惯跨批次累积证据；模型可以引用提供给它的现有同类条目做语义合并，另有精确别名去重。人工决定、拒绝和停用优先。语义合并仍需观察模型质量，不保证完全去重。模型给出的合并目标不存在、超出可选范围、类别不符，或词汇候选要并入另一个不同词名的条目时，只丢弃这一条候选，其余候选照常提交并消耗素材，不因此整批失败。合并保留稳定的习惯正文，避免每批漂移；词汇在第 2、4、8、16 个独立批次可更新释义，内容变化时在审核模式回到待审核。人工编辑或审核过的正文不会自动改写。

0.14 的词汇格式为「词名：释义」。词名至少要在一条引用的目标素材中真实出现，其他引用可用“这个词”等方式说明含义。比较时兼容成对引号、大小写和全角形式，保留存储原文；不将 `rain` 中的 `AI` 或 `deluxe` 中的 `LUX` 算作出现。不存在的词名属于证据错误，整批不提交、不消耗素材；格式形状错误才可纠正。出现校验不保证释义正确，仍应审核。

## 学习自检（0.15）

「学习结果入库自检」默认开启，使用同一个学习模型检查引用原文是否支持候选、前提是否被扩大、是否混入人类身份或反转本地词义。它不能改写正文、证据或新增候选。未通过的新候选仍保留证据并进入待审核，即使开启自动生效也不直接激活；未通过的合并更新不修改、加强或停用旧条目。人工批准、修改、拒绝与停用继续优先。

在「学习与参与」展开「查看自检提示与候选」可读原因；学习库中内容未改变的对应候选也显示提示。审核后仍可查看历史判断，模型提示不是强制结论。自检调用失败、超时或两次格式尝试均失败时，本批全部不提交并保留素材，可稍后重试。切换自检开关会使仍在生成且开关已不一致的结果取消，重试时使用新配置。

通常多一次后台模型调用，不增加回复阶段调用；没有候选时不调用自检。关闭后，后续批次回到原有置信度、证据和审核规则；待审条目仍可能在未来符合条件的批次被自动激活，已有人工作出决定的条目不受影响。自检与提取共用 180 秒后台预算，较慢的模型可能需要减少批量或关闭自检。自检是模型辅助，不保证语义正确。[真实验证与限制](../evaluation/learning-review.md)。

## 习惯检索与反馈

「习惯检索方式」新安装默认「按当前对话筛选」(`contextual`)。先结合文字、可选向量召回最多 24 条候选，再可选使用重排序模型排列候选，最后结合当前输入、最近带角色的对话、宿主人格与人工底稿选择 0–5 条（也受每次应用条数上限限制）。不匹配时可以不选；只返回本次提供的条目 ID，不允许模型改写或自行创建条目。自主参与的回复目标也进入筛选上下文。

每次有生效条目的回复最多额外调用一次学习模型，未指定则用当前聊天模型。情境筛选默认等待 12 秒，独立于向量与重排序共用的 6 秒预算；各最多两个并发，繁忙时不排队。筛选超时、报错或 ID 无效时，不追加表达、性格与行为习惯，保留宿主人格与人工底稿。0.14 起，当前原始消息直接命中的生效词汇仍作为本地事实优先提供，不受表达筛选空选或失败影响。直接命中只看当前输入，不把历史和参与目标当成强制命中来源；常规语境筛选仍可根据上下文选择相关词汇。词汇与其他条目合计仍受原有条数和字符预算限制。调用结束后重新检查会话、设置、底稿和条目状态，停用或修改中的结果不会迟到生效。

「语义与文字结合」(`hybrid`) 和「仅文字相关性」(`lexical`) 保持可用，已保存的选择不会被升级覆盖。相关性排序结合证据、新鲜度、明确评价与引用多样性，但不能保证候选适合当下。仅聊天模型不能作为 embedding 或 rerank 模型使用。

最近对话和查询向量只在内存中短暂缓存。习惯向量按模型和正文缓存到 SQLite，修改内容或模型会重建。首次每次最多补齐 64 条条目，后续回复逐步扩大覆盖；检索状态显示覆盖数量。免费预览不调用任何模型，只展示文字排序结果；真实回复还会经过所选筛选过程，因此可能不同。

学习库可以调整「更合适 / 不太合适 / 清除评价」。这是可撤销的明确评价，影响后续排序，不会改变条目审核状态。引用次数仅记录宿主发送阶段的提示词引用，不等同于真实送达、模型采纳或积极反馈。新鲜度随时间平滑降低，条目不自动删除。

## 原生核心的本地模拟（0.9）

本地验收可运行 `scripts/evaluate_native.py`。它创建临时 AstrBot 数据目录，复制插件并核对 Python 文件字节，使用真实核心初始化、插件加载、九阶段流水线、权限和会话服务；只将群聊发送方法换成收集器。不会连接 QQ 或启动 Dashboard HTTP 端口，也不修改现有宿主副本的数据。

`--smoke` 无需密钥，验证原生 `/sid` 不进入素材，并检查原生 Panel ASGI 接口的鉴权、设置保存、View 页面和脚本。完整模式还使用环境变量中的聊天/硅基流动密钥执行学习、自主生成、直接唤醒及停用会话测试。后台定时学习在验收中取消，由脚本明确触发批次，以保持输入边界；并非替换学习或生成实现。与本次用户选择一致，当前接受范围为本地模拟。

AstrBot 会先移除唤醒前缀，再执行被动过滤器。0.9 同时检查 `message_obj.message_str` 中的平台原文与处理后的文字，防止 `/sid` 等前缀消息在变成 `sid` 后进入长期学习。设置中的自定义唤醒前缀同样参与此检查。

权限和人格读取可能异步乱序完成。较早输入现在仍加入该会话的近期上下文，但只有群内最新事件可以接管等待窗口；等待结束后统一读取消息计数与快照。上下文按原生到达时间排序，不用平台消息 ID 推断先后；时间相等时保持收集顺序。原有新输入中断、共享冷却、排队及发送前复核仍有效。

完整命令、证据与未覆盖范围见 [原生核心验证](../evaluation/native.md)。0.16 起，脚本会记录提取和自检各阶段耗时，`--chat-timeout` 控制提供商单次请求时限，默认 120 秒，与本地 AstrBot 的 OpenAI 提供商默认值一致。插件整批受 180 秒后台预算约束；该脚本参数仅用于本地验收，不修改现有用户的模型配置。

## 筛选时理解最近对话（0.8）

真实回复的检索与情境筛选会读取请求中最近 6 条历史记录里的 user/assistant 普通文字，兼容 AstrBot 的纯字符串与 `type=text` 分块格式。工具、系统、检查点、思考和媒体块不参与；标为临时的文字也跳过。这里只约束本插件转交给筛选器的聊天语境，不删除宿主最终回复所需的工具结果或系统规则。

自主参与时，筛选还读取已准入决策中同一会话/人格的最近 6 条群聊，优先保留较新的上下文；不依赖稍后才执行的上下文附加钩子。最多保留 1100 字符的完整上下文行，当前输入最多 1000 字符，参与目标最多 240 字符，总查询不超过 2400 字符，不增加模型调用或持久化副本。当前输入的明确话题/语气要求仍优先于旧聊天；原生历史、用户原文和其他插件内容保持不变。

原生钩子顺序、分块兼容与真实模型验证见 [对话上下文验证](../evaluation/context.md)。

## 习惯合并与独立批次（0.7）

相近字面不等于同一习惯。“需要建议”和“不需要建议”只差一个字，却是不同前提。新版本仅通过精确别名或模型在已提供的同类条目中指定 `merge_id` 合并，不使用文字相似度自动判定语义。模型仍可能判断错误，审核与人工修改继续有效；没有合并依据时可留下两个待审核候选，而不替操作者猜测。

0.15.1 起，启用入库自检时，明确指定合并目标的候选会同时提供旧条目的内容、情境和状态。即使新候选有原文支持，若它与目标的含义或使用条件不相容，也不能给旧条目追加支持；候选和原因保留在批次自检记录，旧条目保持不变。允许同义改述与有证据的同词释义细化。若自检期间人工更改了目标，整批结果取消并保留素材，重新学习会使用新目标。关闭自检时仍沿用既有的别名、类别和 ID 校验，不进行这次模型语义检查。[实际模型合并诊断与限制](../evaluation/consolidation.md)。

自检还会保留同批中被引回复紧邻的提问，避免把已存在的“只想倾诉”等前提误判成缺少依据；与已有语境合计最多 16 段、每段 400 字。它们只解释使用条件，不追加学习证据或支持批次，也不能将提问者的姓名、职业、偏好变成机器人自己的事实。

一个成功的学习批次对同一习惯最多增加一次 `support_count`。同批多个候选的新证据继续去重累计，置信度先按同批候选平均，再与已有独立批次的均值合成，不把模型重复输出当作多次独立观察。自动生效使用事务内最终汇总值，原本待审核的条目不能靠同批先出现的高分绕过门槛；既有生效状态与人工决定不会因分数变化而自动撤回。

词汇仍在独立批次 2、4、8、16 时核对释义，同批重复候选不能推进多个阶段。升级不改数据库结构，也不重算历史计数：旧库没有足够信息可靠区分曾经多算的候选。从新批次开始使用修正规则。确定性回归与真实模型的四批学习回放见 [学习演变验证](../evaluation/evolution.md)。

## 隔离会话的群聊协调（0.6）

AstrBot 的“独立会话”会把同一群里不同发送者映射成不同 `unified_msg_origin`。学习、人设、采集和提供给模型的聊天上下文仍按原会话隔离；本插件只按平台实例、机器人账号与群 ID 共享参与冷却、每小时限额和最新事件标记。不会把其他隔离会话的消息正文或习惯带进本次模型请求。

直接唤醒、命令和新的群消息在通过现有访问规则后，可以打断旧规划；关闭学习时仍有效。迟到的旧采集与同一事件重复回调不会覆盖最新标记。排队中的自主请求与发送前结果也检查群内最新事件。原生发送阶段的回复会推迟同群其他隔离会话的自主参与；已发出的流式片段无法收回。

独立会话模式下，最少新消息门槛仍由每个会话自己满足，不跨用户拼接上下文；如果希望整群多人对话成为同一段上下文，应在宿主使用共享群会话。数据库自动补充群协调字段，旧决策、原会话冷却和限额继续保留；旧记录无法可靠还原实际群，因此共享群计数从升级后的新记录开始。

原生调度回放与未验证范围见 [原生调度验证](../evaluation/participation.md)。

## 提示投递兼容

在「学习设置 → 记忆与表达 → 提示投递方式」选择：

- **仅系统提示词** (`system`)：默认行为，向原有系统提示词补充人格底稿与选中习惯。
- **系统与临时上下文** (`dual`)：同时把当前宿主角色资料和本轮选中习惯放进原生额外用户内容，适合实际未遵循 system 角色或语气的接口。角色资料来自当前会话绑定的人格，不复制完整系统提示词中的记忆、工具或其他插件内容。

兼容上下文与习惯共用 `prompt_budget`，角色正文最多占三分之一，其余用于说明和表达参考。原系统提示词仍保留；用户原文、模型、工具集和宿主规则不被替换。若没有生效习惯，也可附加已有角色资料。暂停应用时不附加。关闭学习时仅创建会话元数据以应用角色，不因此采集原始聊天。

兼容资料和自主参与的最近消息、回复目标使用 AstrBot 临时内容标记。原生 Agent 持久化消息时会移除这些部分，保留用户原文及其他插件的正常内容；第三方运行器需要自行支持该机制。免费预览不调用模型，也不模拟兼容投递中的角色资料。

在用户提供接口的合成测试中，system 中要求的角色名、固定标记和句式没有生效；同样资料放入用户上下文后，能回答“小夏”并采用学到的轻松反问。这是该接口的观察结果，不能确定网关是否移除了 system，也不代表所有模型需要兼容模式。完整结果见 [学习到回复验证](../evaluation/lifecycle.md)。

## 自主参与群聊

0.3 将原「学习记录」页更名为「学习与参与」，地址与原生 View 不变。参与设置位于「学习设置」首组。

| 参与方式 | 行为 |
| --- | --- |
| 关闭（默认） | 不增加群聊参与；学习与普通回复仍按原设置工作 |
| 仅观察 | 满足门槛时调用决策模型并记录判断，绝不主动生成回复 |
| 自动参与 | 决策为 reply 且把握达标时，创建原生 Agent 请求；可等待一次或保持旁观 |

只对普通群聊文字输入决策，不接管私聊、命令和直接唤醒。需要 AstrBot **本地 Agent 运行器** 执行自动回复；外部运行器可用仅观察模式。普通全消息监听器可并用；已匹配命令、已有请求或已有发送结果优先，不再重复参与。

默认至少 3 条新输入，等待 2 秒以合并连续消息；新消息会取消旧模型任务。模型可以选择 1–30 秒等待，最多等待后复判一次，不循环等待。最后一条真实事件在管线中保留到决策结束，不伪造新平台事件、不重新投递消息。

默认回复冷却 90 秒，同一实际群聊每小时最多 12 次自主参与，隔离会话共享这些限制；原会话限制也继续检查。通过参与门槛时即占用一次尝试，平台失败不会被当成可无限重发的理由。直接唤醒的回复也会推迟下一次自主参与，但不消耗自主参与小时配额。冷却与配额持久化，重载不能绕过。每个会话最多每 30 秒开始一轮决策；冷却小于 30 秒时使用该冷却。尚未满门槛、冷却或并发满时等下一条新消息再检查。

决策模型 ID 留空时依次使用学习模型、会话当前模型。默认单次 20 秒超时，出错或格式异常时保持旁观，原因显示在「学习与参与」。模型没有工具执行能力，只输出行动、理由、回复目标和要回应的最近消息编号；真正的回复交给宿主，保留原有人格和最新会话历史。发送前引用/@ 会绑定到所选消息与发送者，避免挂到最新一条别人（包括另一个 AI）的消息下。迟到的请求会再检查新输入、应用开关、会话权限和人格变化。

「自主回复可用工具」从 AstrBot 当前工具目录勾选，白名单留空只发文字；黑名单排除所选工具，其余仍受宿主权限约束。插件只缩小自主请求已有的工具集合，不会凭空增加工具或提升权限。直接唤醒继续使用原来的工具设置。选择自动参与后，放行的工具可能被宿主 Agent 自主调用。

宿主的 Agent 运行器若把工具 schema 模式设为 `skills_like`，0.22.1 起插件会移除所有未放行或宿主停用的工具，仅用一个初始化兼容包装让真正的空工具集也能完成原生初始化：AstrBot 4.29.1 原本在该模式下遇到空工具集会提前返回，导致 `'ToolLoopAgentRunner' object has no attribute 'stats'`。包装不保留被禁用工具的处理器，派生给模型的工具 schema 仍为空。两种模式均在原生按名查找工具时执行白/黑名单约束，模型猜中一个隐藏名字也不能调用。

参与上下文只在内存保留十分钟内最多 30 条消息，每次给回复模型最多 12 条；不写入第二份原始聊天库。决策理由、目标和时间写入 SQLite，页面展示最近 30 条，保留最近 100 条与当前小时配额记录。清除原始学习素材不会删除决策记录。界面的「交给宿主」不是模型生成成功或平台送达的证明。

## 提示词模板（0.19）

插件发给模型的每一段提示词都在「提示词」页签里，出厂文本可读、可改、可还原。左侧是模板列表，右侧是编辑区：正文、受支持的变量说明、出厂默认全文。

| 模板 | 用在哪 | 变量 |
| --- | --- | --- |
| 参与决策器 | 自主参与前判断回复、等待或旁观 | `{{persona}}` `{{profile}}` `{{guidance}}` `{{recent_messages}}` `{{max_wait}}` `{{wait_elapsed}}` `{{scope}}` |
| 习惯选择器 | 回复前从候选里挑出适合当前情境的条目 | `{{persona}}` `{{conversation}}` `{{max_selected}}` `{{candidates}}` |
| 学习分析器 | 从原文里提取人格、表达、词汇与行为习惯 | `{{persona}}` `{{profile}}` `{{observations}}` `{{memory}}` `{{context}}` `{{known_traits}}` `{{language_features}}` `{{enabled_kinds}}` `{{min_evidence}}` |
| 入库自检器 | 逐项核对学习结果是否被原文支持 | `{{persona}}` `{{profile}}` `{{observations}}` `{{context}}` `{{memory}}` `{{candidates}}` |
| 表达参考基调 | 追加在补充习惯之前的总则 | `{{profile}}` |
| 自主参与：系统提示 | 自主回复请求里追加的系统提示开头 | `{{goal}}` `{{reason}}` `{{target}}` `{{profile}}` `{{scope}}` |
| 自主参与：临时上下文 | 随本轮请求附带的群聊上下文说明 | `{{reply_goal}}` `{{target}}` `{{messages}}` `{{profile}}` `{{scope}}` |
| 回复装饰约束 | 追加在自主回复请求里，禁止正文伪造 @ 或引用标记 | 无 |

变量在调用时替换：文字原样插入，消息列表、候选习惯、底稿这类结构化值序列化为 JSON，布尔值写成 `true`/`false`。写错的名字不会被替换，会带着双花括号原样留在提示词里，编辑区会把它列在「未识别的引用」下——这是刻意的：静默清空会让模型少掉一整段约束而不报错。

模板只改变措辞。引用展开后的结构化 JSON 载荷、参与目标与理由、权限检查、工具白名单、冷却和小时配额仍由插件追加或校验，所以改写决策器不会放宽参与条件。保存会校验非空与 8000 字上限，立即重建生效模板并中止在途学习批次和参与窗口；「恢复默认」删除该条覆盖。覆盖存在 SQLite 的 `prompts` 表，重载插件后仍在，卸载插件数据库则一并清除。

提示词正文同时作为该请求的 system prompt 发送并记录在 Debug 的 `planner_request`、`planner_response`、学习与检索条目中，所以排查时看到的确实是跑过的那份措辞。若想让决策模型带上关系与情绪，把关系设定写进人格（它会通过 `{{persona}}` 进入决策器），再在决策器模板里补上对这类场景的具体要求。

## 与记忆插件配合

启用 LivingMemory 的联动开关即可，无需填写端口、URL 或令牌。插件发现已启用且就绪的 LivingMemory 实例后，按它的权限、记忆作用域和人格过滤规则检索。默认最多取三条上下文，仅帮助理解素材，不能代替原始聊天证据。重载后尚未收到该会话的新事件时，该批只使用已保留的原始聊天素材。

0.12 起，旧版模式下关闭会话过滤、且没有配置强制隔离列表时，准确保留 LivingMemory 的不分会话检索；启用人格过滤时仍只检索当前人格。存在隔离列表时则复用它的全局池与隔离会话规则，不由本插件自行扩大范围。真实记忆引擎的合成数据验收见 [联动验证](../evaluation/memory.md)。

这是可选联动；接口不兼容、未安装、未就绪、被停用、权限禁止或检索超时会在学习记录中解释，不中断独立学习。实际记忆检索可能更新 LivingMemory 的访问时间，并可能运行其原有旧作用域迁移。本插件不向 LivingMemory 写入额外记忆。

QQ 能力增强可同时启用，无需特殊适配。自主参与默认禁用工具；按名称放行后，仍通过宿主正常工具链执行，并受 QQ 增强原有权限与确认机制约束。直接唤醒的原工具策略保持原样。

## 应用参考（0.13）

0.13 的应用提示将人格边界视为生成约束，避免在介绍身份时复述内部规则；不会用闲聊短句限制用户明确要求的完整解释。修改没有新增模型调用或配置项。固定学习结果的本地对照与仍存在的冗长问题见 [应用规则验证](../evaluation/application.md)。

## 保留与恢复

默认原始素材保留 14 天，每个会话人格最多 300 条。定期清理在后台进行，素材满额时淘汰最旧消息。每条保留最近 32 条证据摘录与累计计数；学习结果、证据摘录与修改快照不随原始素材过期而清除；原始素材清除按钮也不会删除证据摘录。

学习合并、人格、条目编辑、评价和审核前自动保存快照，最多 30 份。恢复将还原该快照的底稿与旧条目状态，把之后新增的条目停用；恢复操作本身也留快照，可以再次恢复。素材清除不可撤销，恢复快照不能恢复原始消息。

人格底稿、学习条目和记录位于 `data/plugin_data/astrbot_plugin_ovenheart/persona.sqlite3`，全局设置位于 `data/config/astrbot_plugin_ovenheart_config.json`。备份时建议先停用本插件，同时备份插件数据目录和这份宿主 config，避免漏掉 SQLite 的 WAL 文件或全局设置。

## Debug 模式（0.17）

在「学习设置 → 调试日志」启用「启用 Debug 模式」并保存，或在宿主插件配置设置 `debug_enabled: true`。默认关闭；工坊与宿主插件配置使用同一份设置。日志使用 INFO 级别，宿主需允许 INFO 日志；在 AstrBot 日志搜索 `OvenHeart debug`。关闭后立即停止后续调试输出。

- `persona_injection`：本插件实际追加的完整 system 内容与兼容模式临时用户上下文，包含会话、人格、实际纳入的条目 ID 和投递方式。不会把无关的宿主原始提示词一起转储。
- `participation_injection`：自主参与实际追加的系统目标、回应对象、临时群聊上下文与允许的工具名。
- `participation_target`：发送前绑定到的消息编号、发送者、目标消息 ID 与 `decoration` 选择。
- `reply_mentions`：正文里的 `@昵称` 被转换为真实 `At` 组件的数量。
- `retrieval` / `application_skipped`：实际检索查询、候选数量、选中条目、分数、理由、回退信息与应用跳过原因。
- `learning_batch` / `learning_request` / `learning_response`：批次来源 ID、对象、两段提取与格式纠正的完整请求、模型原始返回；不会额外截断。
- `review_request` / `review_response` / `learning_committed`：自检原始输入、返回与最终入库审计。
- `planner_request` / `planner_response` / `participation_plan`：参与规划输入、原始输出和解析决策。
- `capture` / `capture_skipped` / `learning_failed` / `learning_cancelled`：采集路径、跳过原因、失败类型及其直接原因类型、取消与素材保留状态。

日志只序列化明确传入的业务字段，不读取或输出模型配置密钥、HTTP 鉴权头，也不输出可能含凭据的原始供应商异常消息。注入、原文、人格和记忆摘录会完整出现在日志中；调试结束后关闭即可。JSON 字符串中的换行使用 `\n` 表示，内容可无损还原。仅记录本插件的追加内容，不保证下游其他插件或模型提供商不会进一步改写请求。

## 提及时马上回复（0.21）

入口：人格工坊「学习设置 → 提及时马上回复」。原「自主参与群聊」入口保留；新增独立的名字唤醒设置。开启「启用提及回复」，逐行填写「机器人名字与别名」，例如 `小夏`、`夏夏`。默认关闭且名称列表为空。与 AstrBot 插件配置的 `mentioned_bot_reply`、`mention_names` 同步。

名称在群聊当前正文任意位置命中即走宿主原生回复，区分大小写；不检查引用、转发内容或 @他人显示名。自主参与关闭和仅观察时也可生效，跳过其最少新消息、等待、冷却、每小时上限与决策模型。请避免短名称和常用词。

宿主权限、白名单、限流、内容检查、LLM 开关仍有效，工具使用宿主原有策略；自主工具黑白名单只约束普通自主参与。@机器人、引用机器人、唤醒前缀由宿主原生处理，不重复回复，命令优先。禁用开关或移除命中的名字，会在生成/发送前取消尚未交付的名字提及回复。即时表示立即进入原生回复流程，生成和平台发送仍有耗时。
