# 0.67 自动群聊整理与情景记忆

继续对照 MaiBot `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501`，移植原 SummaryImporter、EpisodeService、EpisodeSegmentationService、EpisodeRetrievalService 和 MemoryIngestService 的情景任务路径。新增9个原模块与3份原版摘要语言模板，累计46个模块。原许可证、提交和文件哈希保存在 vendor 清单中。

## 已接通的行为

- 普通获准的人类消息进入现有素材库后，可后台整理；不是只有 Planner 主动要求保存才入记忆。复用现有有界素材库，不另建全文聊天数据库。
- 默认累计12条新素材、最短尝试间隔600秒、每批最多50条。同一时刻最多一个自动整理任务；已有轮询会继续访问近期会话，失败素材保留重试。
- 原摘要器回看至多两份仍有效的旧摘要，只输出增量。原空增量检查点避免重复生成；已处理原生消息ID跨重载保存，并随现有素材清理，不依赖可重用的 SQLite 行号。
- 模型返回需通过整份 schema 和真实原文引用校验，非空摘要必须有本批来源。写入前再检查当前配置、会话、人格、学习许可、成员筛选和素材是否仍保留。来源被清除、撤销或换人格时不提交这份生成。
- 段落、实体和关系仍由原摘要器写入。原文来源是 AstrBot 适配元数据，不将参与者当作每条事实的所有者；重复摘要保留最初与近期原文证据。段落和图向量池均持久化，嵌入失败可留下原始元数据和回填任务。
- 情景使用原版时间区间分组、语义切分、输入指纹缓存、来源任务、租约和版本发布。无意义内容可返回空情景；生成失败不捏造替代经历，保留上次已发布数据。来源尚未完成重建时，不把过时情景注入当前回复。
- 原 EpisodeRetrievalService 的词法与段落/关系证据投影参与召回。当前通用检索保留至多一条相关情景及原段落/关系，总数仍受 `memory_top_k` 控制。Planner 与直接/自主回复器共用该通道，内部经历使用临时内容，不写成用户发言或宿主历史。
- `memory_summary_enabled`、`memory_summary_min_messages`、`memory_summary_interval` 和 `memory_summary_provider_id` 均可在原生工坊管理。暂停学习会停止更新，已有获准记忆仍可读取。摘要和切分分别计入 `memory_summary` / `memory_episode` 辅助用量。

## 宿主适配与尚未完成的范围

`summary_host.py` 只提供获准的原生文字快照、原版模板和模型运输；没有注册全局 MaiBot 模块。原摘要器的嵌入自检绑定到已初始化的 RoomState，模型选择与向量空间由 AstrBot 提供。文本入口明确不提供图片证据，完整图片链仍待实现。

整理、前台查询和记忆工具写入现在共用一个持续运行的后台事件循环。整理等待模型时，前台可借用同一份已提交存储完成查询/保存；后台恢复提交前先关闭借用窗口并等待已经开始的前台操作完成。前台操作彼此串行，原始作用域和学习许可继续校验；切换向量空间、LRU释放和关闭会等待已登记操作结束。查询取消只取消本次查询，配置更新取消旧整理任务，操作取消须等待后台清理确认，关闭时回收线程。

前台嵌入失败后，摘要提交重新绑定内核当前有效的向量池，避免覆盖前台写入。Planner保存与自动摘要使用同一原生会话来源。情景模型等待期间新增来源会触发原版revision CAS拒绝过时物化，保留原始段落并等待下一轮重建。后续阶段已将存储所有权、公共写入、摘要入口与情景物化交给实际 SDKMemoryKernel，原临时情景运行器已移除；剩余后台消息桥见 [native-memory-kernel.md](native-memory-kernel.md)。

独立中期记忆、人物近期/关系与情景的进一步贯通、通用纠错/遗忘和维护、图片/表情行动、旧 LivingMemory 数据导入、直接唤醒统一规划，以及真实模型的完整文本对照仍未完成。LivingMemory 及其已有数据保留，本阶段没有部署。

## 验证

本次调度修复后799项完整 Python 回归通过，包含真实安装包独立导入和原版来源/算法主体对照；Ruff通过。前端源码未改动，沿用上一阶段31项前端及JS语法验证。新增回归使用真实 SQLite、图与 Faiss，仅替换外部模型传输，覆盖来源伪造、空增量、失败重试、权限/人格撤销、清空素材、取消、重载、双向量池与重复证据。

另以本机 AstrBot 4.29.1 的完整内核、原生装载器和事件管线，验证普通群消息自动整理、情景召回、Planner/回复器共享、无额外可见发送和历史不保存内部经历。模型输出与发送端为受控响应/回环；未向 QQ 发消息，也未将这些结果当作真实语义质量或拟人程度验收。

慢模型回归先复现了同会话查询超时；完整宿主又发现Planner的记忆写入也会等待后台模型。修复后验证查询与保存可在模型暂停期间完成、独立取消不影响后台模型、配置变更取消旧任务、恢复索引不丢新向量，以及新增来源导致旧情景物化被CAS拒绝。
