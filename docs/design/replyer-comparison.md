# 回复器实际对照

整体目标仍需要同模型、同人格、同上下文的持续Planner/回复轨迹；单条输出和纯提示词比较不证明整套系统接近MaiBot。

原生工坊preview/model保留实际会话权限与人格检查，但不需要伪造消息事件，不发送QQ、不写宿主聊天历史、学习素材或引用曝光。现在每次调用计入model_preview，并返回provider_id、实际模型名、提供商报告的token和已装入的表达ID；role=err使用固定中文错误，不把提供商错误正文当成回复显示。

首次线上示例（空表达选择）：“今天真的累死了，组里又把烂摊子丢给我。我就想吐槽两句，别给我建议。”得到“听着呢，烂摊子又堆你身上了？”。这只能证明该时点示例遵从倾听要求，未证明连续聊天或与MaiBot一致。

scripts/maibot_replyer_probe.py从固定提交5c7637e6913c84d1c3d5e742fa9e95a7e70d3501直接导入真实MaisakaReplyGenerator，使用它的上下文构造、模型服务和生成/后处理链，不手写替代MaiBot模板。实例通过MAIBOT_INSTANCE_DIR放在源仓库之外；不改参考源码，原生身份适配只逐字返回同一宿主人格。提供商与人格JSON仅从stdin进入进程内存，报告不写密钥、地址、人格原文、请求提示词或推理内容。报告保留合成输入、可见正文、来源提交、模型与用量。

该脚本目前仅用于空表达选择的回复器阶段：未运行完整Planner、表达学习、记忆与平台发送。原生配置未声明输出上限时，参考侧使用4096并在报告明确列出；不能据此声称全部采样条件完全相同。原版在独立临时实例中的导入已验证，真实模型对照仍在接通。
