# Planner 表情与自身媒体

对照固定 MaiBot 的 `show_emoji_list` 与 `reply.attach_emoji`：从真实图片记忆中提取当前会话已被模型识别为表情包的资产，随机展示最多六个候选，模型只能填写当前 Planner 实际提供的序号。普通照片、截图和私人物件没有表情标注就不进入候选。序号进程内递增，每个 Planner 最多保留24个已提供的映射；发送时重新读取原 SDK 的作用域可见性及资产状态，删除后不能使用旧序号发送。

候选拼图的布局、编号角标、占位与PNG合成直接移植原实现，来源和符号 AST 哈希见 `vendor/maibot/emoji_source.json`。`planner_visual_enabled` 默认关闭，以原有描述选择；确认 Planner 模型支持图片后可开启，原生工具结果会把拼图送入模型内部上下文。拼图不会作为聊天消息发送；实际发送只接受候选资产的序号，不接受模型编造的文件路径。`emoji_enabled` 可单独关闭动作。

Planner 的 reply 提交文字策略和可选 `attach_emoji`。只有原生文字回复已到发送钩子、当前 Planner 和权限仍有效时，才调用原生事件发送单张选定表情。动作返回真实适配器结果和选中描述，继续进入同一个工具循环；失败明确返回 `sent=false`，不撤销已经发送的文字，也不生成虚构的媒体发送记录。原生发送返回与平台最终回执分别表述。

自己的图片发送由绑定在当前原生事件上的发送观察器登记，保留原平台实现，不改全局适配器。结构化模式继续使用已有持久上下文；原生模式在已有 Planner 窗口追加有实际发送依据的自身媒体行。混合消息中的图片只有精确匹配的显式选择或独立表情发送元数据才可使用候选描述。媒体临时文件在发送方清理前转换为有大小限制的真实字节，并由同一原图片 SDK 建立 `bot` 出现记录；不作为原触发作者的自我陈述。

已知表情描述立即进入下一轮；原生未知图片可后台补充描述，结构化模式沿用已有异步描述槽。晚到的自身图片描述通过原 SDK 的同图描述/待补偿机制登记，不错写到触发用户的图片上。学习暂停后不再保存新自身图片，实际发送后的上下文反馈仍保留。

独立 `send_emoji()` 不生成正文，先经过相同参与判断，再用最近十二条真实上下文和原候选拼图调用视觉子代理。选择结构、中文提示与无效序号回退首项行为保留原实现。`emoji_provider_id` 优先；留空时使用已启用视觉的 Planner 模型，否则使用宿主图片描述模型。没有视觉模型或模型请求失败时不发送，明确反馈错误；子代理调用受 Planner 超时限制，计入 `emoji_select` 用量。

独立媒体成功后更新实际回复节奏和冷却，并将自身媒体带入后续规划；失败释放未完成的参与预留。纯表情不把同一消息的具体文字任务标为已完成，直接请求仍可继续文字处理；同一输入不能连续重复纯表情回应。这样零群聊参与频率也不会因为一次失败或表情回应就阻断尚未完成的明确请求。

定向验收使用实际 AstrBot 工具循环、MCP图片工具结果、原拼图算法、原图片资产及原生消息链，只替换外部模型和IM运输。覆盖查看拼图、真实序号、文字后发送、发送成功/失败回流、自身媒体上下文与 `bot` 资产来源；独立视觉选择、原无效序号回退、纯媒体回执及模型失败后继续零频率直接请求。未做真实模型挑选质量、QQ回执和完整分段节奏验收。
