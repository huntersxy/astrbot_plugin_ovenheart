# 原生图片记忆

图片资产、出现记录、观察版本、二进制嵌入探测、向量任务、同图/相似图检索及关联展开使用固定 MaiBot 来源的原 `ImageMemoryRuntime`，没有建立第二套图片索引算法。AstrBot 适配在根目录 `image_memory.py`；仅在原生消息、工具或媒体动作涉及图片后启用该作用域的图片运行时，普通文字记忆不会启动图片模型探测。

每张图片使用真实平台消息、作用域、组件序号和时间建立原出现记录；纯图片消息也可写入。作者随图原话属于 `user_statement`，视觉模型描述属于未确认的 `model_description`，两者分开。描述复用宿主 `provider_ltm_settings.image_caption_provider_id`，以实际图片调用模型并计入辅助用量；模型可标注是否为表情包，普通照片、截图及私人物件不会被该标注自动提升为表情包。模型未按JSON返回时仍可作为普通描述使用，但不标注为表情包。

`query_image_memory(msg_id,image_index)` 只能定位本轮真实原生来源，复核作者、会话和人格；返回当前图片描述及原 SDK 的历史同图、相似图和关联记忆。没有描述模型时明确返回不可用，不能假装看懂图片。当前出现从历史候选中排除，跨会话不能通过猜图片编号访问。

图片相似检索使用配置的 AstrBot 原生 DashScope 多模态嵌入提供商及其真实图片请求协议，复用已有提供商配置；未配置时仍支持真实字节哈希同图召回，不把描述文字向量当作图片向量。二进制 `input=[{"image":"data:image/...;base64,..."}]` 及返回结构已按[官方 API 文档](https://help.aliyun.com/en/model-studio/multimodal-embedding-api-reference)核对。沿用原三张探测图片、同图一致性与不同图可区分性验证、嵌入指纹和向量空间隔离。图片模型与正文/文字嵌入模型分别配置，不保存密钥。GIF 在原资产存储适配中保留原始动画，嵌入使用首帧并纳入协议指纹。

写入、描述存储和后台图片索引受当前应用、学习、作者及原生会话权限控制；暂停学习后不再领取图片索引任务。图片模型请求前后复核权限。原 SDK 资产发布、恢复、租约及删除联动保持原实现。宿主自身图片理解和工具权限仍由 AstrBot 负责。

两个定向场景使用真实 SDK 资产、SQLite、原二进制探测/向量任务/Faiss 和原检索：原生图片及描述入库、实际同图和相似图命中、二进制协议、暂停学习；纯图片 GIF、无图片嵌入时同图命中和跨群拒绝。只替换外部模型运输，没有真实供应商或 QQ 质量验收，未跑全量回归。后续已接入表情包候选、文字后的显式发送和自身媒体反馈，见 [emoji-actions.md](emoji-actions.md)。
