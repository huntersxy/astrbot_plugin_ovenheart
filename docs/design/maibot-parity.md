# MaiBot 聊天机制复刻目标与验收

目标原文：接下来的目标是要几乎复刻一个 MaiBot；已安装的记忆插件不顺用时，允许移植 MaiBot 的记忆实现。

该目标保持完整。不能将某个门控、提示词、接口适配或若干测试通过当作整体完成。这里跟踪实际聊天系统：参与、持续规划、人物理解、记忆、学习、表达、媒体和发送协同；宿主权限、真实消息来源和用户已有数据继续保留。

资源规则：按用户2026-10-26最新要求继续，保留10%额度；以实现为主，只做改动必要的定向检查，发布前再集中验收。此规则替代此前保留50%的停止线。

## 已经落地的第一部分

- `vendor/maibot/dynamic_gate.py` 与 `reply_likelihood.py` 为原提交逐字节移植；原 GPL 文本与文件哈希见同目录 NOTICE。
- `rhythm.py` 只负责把 AstrBot 的真实到达和回复事件转换为原算法输入，不另建聊天正文历史。
- `participation_rhythm=maibot` 使用动态频率门控；`fixed` 保留旧配置行为。频率是目标回复比例，不是逐条随机概率。
- 宿主权限、会话开关和显式的每小时额度仍是操作者策略，不被算法绕过。固定消息数、判断间隔与回复冷却不再叠加在动态模式上。
