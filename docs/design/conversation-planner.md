# 0.67 持续聊天规划

本轮将自主参与从单次 Jev / JSON 判断接到 AstrBot 原生 `Context.tool_loop_agent`。动作契约对照本机 MaiBot `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501` 的 `src/maisaka/builtin_tool/{reply,wait,stop}.py`；本模块是自有 AstrBot 适配，没有修改第三方仓库。

## 实际执行链

1. 原生权限、会话和动态节奏允许进入规划后，用当前人格、真实有界消息、相关习惯和获准的记忆建立一个独立工具循环。
2. `search_memory(query)` 可进一步查询背景，继续使用 LivingMemory 的会话、人格及访问策略。查询词不改变可访问的范围；未确定对象时不读个人作用域。
3. `reply(msg_id, reply_reference, reply_style, expression_intent, decoration)` 选择真实可回复消息。`reply_reference` 必须非空，最多2400字；篇幅使用 MaiBot 的简短表达、正常回复、长回复。内部参考作为临时内容交给实际回复器，不存成用户发言。
4. 动作暂停在 Future 上，插件生成器交出原生 ProviderRequest。AstrBot 照常完成权限工具筛选、记忆 hook、模型生成、历史保存、装饰和发送。
5. 发送钩子记录实际回复文本，再解除工具暂停。同一个 Planner 收到工具结果后继续判断，可处理另一个真实对象，不另开一轮没有前情的判断。发送钩子只证明到达宿主发送边界，不证明 QQ 客户端收到了消息。
6. `wait(seconds)` 暂停，到期后继续；新的获准输入可在新事件处理器接续同一个等待中的工具循环，工具结果明确区分 timeout / new_messages。单次时长取配置上限，连续等待默认三次，与对照源码默认值一致。
7. `stop()` 或没有工具行动时结束，不额外生成一条可见“结束”消息。SDK 每条规划链最多16步；相同目标已经发送后拒绝再次回答，防止把循环变成重复刷屏。

Planner 的思考和查询结果不会发送到群内，也不进入宿主可见聊天历史。自主任务的实际操作仍由原生回复器执行，其工具来自宿主授权集合并继续经过本插件自主工具策略；本轮没有把全局工具管理器直接暴露给 Planner。

## 旧机制与原生边界

- `planner_mode=maibot` 是开发版默认；使用配置的参与决策模型及单次决策超时。Jev 继续辅助表达筛选，不再接管这条规划链。
- `planner_mode=legacy` 保留原 Jev / JSON 单次判断。固定静默收集仅用于该方式，避免持续 Planner 的 wait 上再叠一层固定窗口。
- 动态节奏不再套用旧“续接只能回应上一位成员”的固定模式例外。每次真实自主回复仍单独占用操作者每小时额度。
- 回复装饰会临时修改原事件的引用 ID 和发送者；每次原生请求结束后恢复，并固定原到达事件的 source。否则旧目标可能污染后续规划和来源校验。
- 每次回复重新绑定记忆来源。先回较早成员、再回触发成员时，必须释放上一条的来源代理，不能沿用旧人身份进行召回和反思。
- 新的直接唤醒优先取消同群 Planner；本插件自己的原生请求不被误认成新的直接唤醒。查询前后复核配置版本、作用域、人格和底稿，撤销后取消规划。
- 回复已经到达发送钩子后，后续撤销只停止新行动，不把之前已消耗的参与额度改成取消。

## 群聊直接唤醒统一规划

`planner_mode=maibot` 下，原生 @、回复唤醒、前缀唤醒和配置的名字提及进入同一个工具循环。`trigger.route=direct` 与真实 `msg_id` 标记明确请求；首条回复先处理当前叫它的成员，能先查询背景，发送后的真实正文和回执继续返回同一 Planner。命令处理器、已处理消息、关闭的宿主 AI、暂停应用和非本地 Agent 仍保留原生路径。

- 明确请求的首条回复绕过自主参与开关、概率、静默等待、冷却和每小时自主额度，仍复核宿主权限、人格、会话底稿和真实目标。记录模式为 `direct`，不占自主额度；追加回复恢复自主策略。
- 直接请求通过宿主 `collect_initial_request` 收集原始图片、语音、文件、引用、所选模型和原生历史，再交给相同回复管线。首条保留宿主已授权工具；追加主动回复恢复自主工具策略。没有通过 Planner 把全局工具开放给模型。
- 普通插话不撤销尚未完成的明确请求；这些真实输入进入上下文，首条发送后 Planner 能继续处理。新的明确唤醒仍能撤销旧 Planner。同一成员对尚未完成请求追加空 @ 时，在被动采集和优先处理两种时序下都沿用已有请求。
- `stop` 和正常结束会抑制宿主再次自动生成；模型错误或超时在尚未交出回复请求时保留原生请求回退。原生 SDK 返回 `role=err` 也按失败处理，不当作正常结束。

## 私聊统一规划

宿主已经判定唤醒的原生私聊也进入相同 Planner，遵守宿主的私聊唤醒前缀设置。协调键按平台、机器人、消息类型和实际私聊会话隔离，不与群聊或其他私聊混用。查询、人物画像、回复策略及实际发送结果继续走相同管线。

私聊后续行动围绕当前请求继续，不使用群聊的抢话频率、冷却及自主额度；仍记录 `direct` 决策，并受宿主权限、应用、模型配置和 Planner 步数限制。每次追加生成重新调用宿主请求收集器，获取当前历史、模型、媒体和已授权工具，避免复用首条请求中已修改的临时上下文。完成后由 stop 结束，不额外生成一条原生默认回复。

定向核对覆盖私聊查询/回复/回执、非唤醒拒绝、不同私聊隔离，以及零群聊频率下的两次回复和新原生请求/工具保留；同时核对已有直接唤醒入口。只使用受控模型运输。

## 验证和剩余工作

测试使用实际 AstrBot SDK 工具循环及工具执行器，只替换模型传输。另在隔离 AstrBot 完整内核中，用合成群消息覆盖两名真实目标、两次原生生成、发送结果回流、历史保存和 stop；没有向 QQ 发送消息。

本轮完整 Python 回归753项通过；随后补充并修复“已发送后撤销不得释放额度”的真实存储回归，Planner 与完整宿主定向复核12项通过。31项前端测试、Ruff、JS语法及安装包独立导入检查通过。SDK为本机AstrBot 4.29.1；没有把这些合成模型响应当成同模型自然表达验收。

新增完整宿主回放覆盖关闭自主参与和零频率下的原生 @：查询、一次实际回复、回执回流、停止和原生历史保存；内部参考未进入历史。定向回归同时覆盖额度耗尽、普通插话、两种上下文模式、原始图片/引用及模型选择、首条工具权限、空 @ 合并和模型失败回退。受控模型响应验证调度行为，不证明自然表达质量。

后续阶段已由原记忆 SDK 接管聊天存储，并加入有真实请求依据的通用更正、遗忘及同作者撤销。操作结果进入同一工具循环，回复器读取同一份生效记录；需要撤销近期操作时不依赖旧 Planner 仍在运行。细节与边界见 [native-memory-kernel.md](native-memory-kernel.md)。

Planner 原生工具循环已逐次统计实际模型运输，查询/回复/停止等工具往返中的每次调用均进入原辅助用量聚合，包含提供商上报的缓存、输入及输出 token、失败和取消；工具等待不算模型运输耗时。通过仅属于当前循环的 Context 和提供商副本绑定计量，运输仍调用原客户端，不改共享提供商或重复计入辅助 generate。正文回复继续沿用宿主本身统计，尚未将宿主正文统计合并到插件面板。未上报 token 的请求保持未上报，不猜测数值；只保存统计，不保存提示或正文。

后续已接入真实图片查询、候选拼图、reply 附带表情及独立纯表情视觉子代理，实际发送结果和自身媒体进入后续规划，见 [emoji-actions.md](emoji-actions.md)。这仍不是整体复刻完成：完整分段节奏、宿主正文用量合并和同模型完整文本对照仍需继续。动态后台反馈已在后续阶段接入。等待状态目前只在当前进程内保留，不宣称重启后恢复。线上仍是已部署的0.66，本轮0.67开发代码未部署。
