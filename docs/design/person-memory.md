# 0.67 人物事实与画像

本轮确认 LivingMemory 的现有 `search_memories` 与原生召回/反思契约不足以提供 MaiBot 的结构化人物事实账本。保留该插件的已有数据和运行时联动，在烤箱之心自己的 `amemorix/metadata.db` 中接入 A_memorix 人物通道，没有修改第三方仓库。

## 移植范围

对照 MaiBot `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501`，直接移植22个模块，包括原事实状态机、SQLite 元数据存储/版本、画像快照、证据归属和文本投影。原 AGPL 许可证、上游与移植后哈希、适配清单保存在 `vendor/maibot/amemorix`。事实状态机原文不变；人物服务只适配导入、注解及可选检索器构造，其余方法保持原文算法。

AstrBot 适配使用实际平台、机器人、会话、人格和成员 ID 生成独立人物身份；不按昵称推断身份，关闭习惯的会话隔离也不共享人物档案。SQLModel 身份表只记录 SDK 给出的真实成员字段。所有 SQLite 和画像聚合在工作线程运行，不让同步数据库操作占住回复事件循环。没有注册全局 `src` 兼容模块。

## 更新与使用

- `person_memory_enabled` 默认开启，独立于 LivingMemory 的召回开关。沿用宿主权限、允许会话、成员/群聊学习排除和会话底稿的应用/学习开关。
- 同一成员累计六条新素材后可后台提取；默认每600秒最多尝试一次，最多处理30条已有素材。复用原素材库，不另建全文聊天库。失败保留原事实与未处理素材；原生消息 ID 标记处理进度，清空素材或 SQLite 行号重用不会卡住后续更新。
- 模型只提供待校验事实。原文引用必须能在指定真实作者的素材中找到；整批校验通过才提交。每个事实保留来源消息、作者、摘录与记录时间。引用、转述、玩笑、推测在提示中明确排除为稳定自我陈述；语义提取质量仍需真实模型评测，原文匹配本身不证明归纳正确。
- 使用原版 single/set、active/conflicted/superseded/retracted 状态及证据规则。不同单值不会静默覆盖；明确更正须引用当前人物同一属性的事实 ID，不能修改另一个人的事实。失败的批次整体回滚。
- Planner 新增 `query_person_profile(msg_id)` 和 `remember_person_fact(msg_id, facts)`。目标必须是本轮真实成员；写入须有仍获准访问的原事件。记忆动作返回结果后可继续规划，不自动发群消息。
- Planner 和原生回复器读取同一份持久化画像。每轮最多三名成员，每人紧凑参考最多900字；作为临时内容注入，避免将内部档案写进聊天历史。当前明确更正和真实请求优先于旧画像，不背诵档案。
- 不确定信息保存在原“不确定信息”段落，自动注入关闭 uncertain fallback。临时事实保留 temporal 分类，不强行提升为稳定了解；原版近期段落所依赖的摘要/情景检索链尚待接入。

新增运行时依赖为 `json-repair>=0.60.1,<0.61`，与对照来源一致，SQLModel 等沿用 AstrBot。发布前必须先满足安装包依赖预检；本轮没有部署。

## 验证与剩余范围

测试覆盖真实 SQLite/原服务的持久化重开、事实冲突与明确更正、整批来源校验、成员/群聊/人格隔离、暂停学习、自动更新、失败保留、素材清空后的增量处理，以及原生回复临时注入。另用实际 AstrBot 完整内核验证 Planner 写入、查询、回复器读取同一份画像、发送结果回流和历史不保存内部画像；只有模型传输与 IM 发送端采用合成响应/回环。

后续阶段已接入通用写入/检索、自动摘要与情景生成，群聊直接唤醒也已纳入同一 Planner。人物画像与通用/情景检索的进一步贯通、独立中期记忆、图片记忆、通用纠错与遗忘、旧 LivingMemory 数据导入，以及真实模型对照尚未完成。原版相应数据表随元数据存储存在，不代表这些管线已经接通。完整要求继续见 [maibot-parity.md](maibot-parity.md)。

本阶段验证：767项完整 Python 回归、31项前端测试、Ruff、JavaScript语法和实际发布包导入检查通过。SDK为本机AstrBot 4.29.1；767项包含完整宿主的人物记忆共享/临时注入验收，不代表真实模型或QQ实聊验收。
