# A_memorix SDK 内核移植与主链接管

对照仍固定为 MaiBot `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501`。本阶段加入 SDKMemoryKernel、运行时 facade、生命周期、检索执行、模型空间、纠错/回滚、删除/恢复、关系维护和导入管理等依赖；现在保留110个上游 Python 模块与6份原版语言模板。它们位于自有插件的 vendor 命名空间，第三方仓库不变。

## 已运行的内核能力

`NativeMemoryKernel` 继承实际 SDKMemoryKernel，使用原服务装配和 initialize/shutdown 生命周期。测试真实创建 SQLite、GraphStore 和 Faiss，持有数据目录写者锁，启动后台任务并在关闭时等待任务退出、持久化和释放锁；没有用替身模拟这些服务。

- 原 `ingest_text` 统一写入段落、实体、关系、幂等外部来源和派生任务。
- 原模型空间同步、双向量重建与 ready manifest 可实际运行；检索通过真实向量池找到无词面重叠的查询，同时拒绝其他会话的数据。
- 原删除预览、执行、清理任务和恢复可实际运行，删除后的数据不再进入检索，恢复后重新可读。
- 原修正预览、计划执行、失效版本过滤及回滚可实际运行。测试中的模型只提供受控计划，计划校验、存储变化、图谱更新和检索过滤均为原实现。
- 原同步工作边界一并移植：取消时等待真实文件工作结束，再释放生命周期资源，避免关闭后线程继续修改数据。

`sdk_host.py` 是显式的宿主边界：真实数据根目录、嵌入适配器、当前会话、消息快照和模型运输通过上下文绑定，不注册 MaiBot 的全局模块。嵌入向量的实际数量、维度和有限数值由原生适配器验证；只有已观察到的维度才声明 `source=observed`。该声明不改变既有模型指纹 hash，避免仅因增加验证信息而重复建立模型空间。

## 已修复的原版调用边界问题

实际修正曾稳定返回 `database is locked`：失效标记会更新图片关联和事实证据，但原辅助方法将提交交给调用方；随后图谱保存通过另一条连接写入同一数据库，被未结束的写事务阻塞。

`NativeCorrectionService` 只为单个目标的原失效更新补上受管事务，提交后再进入原图谱保存。原修正算法和第三方源码保持原样；真实执行、过滤与回滚回归通过。

## 聊天主链接管

`RoomMemory` 现在只保留原生作用域、来源、权限和工作线程调度；每个 RoomState 由一个实际 `NativeMemoryKernel` 持有 SQLite、GraphStore、稀疏索引与向量空间。通用写入调用原 `ingest_text`，查询调用原 `search_memory`，自动摘要通过原 `summarize_chat_stream` 和公共 ingest 落库，情景物化使用内核已组装的原服务。原临时情景运行器已移除。

- 首次接管旧目录时，在原写者锁内备份一致性 SQLite 和图文件到 `native-kernel-backup`；旧向量文件原样保留。SDK 在 `vectors/spaces` 中建立自己的可验证空间，当前不宣称直接复用旧布局的 Faiss 文件。旧通用来源被规范到当前唯一会话；原文证据不变。
- 初始化先观察提供商真实向量维度；切换模型会关闭旧内核并以新指纹恢复，旧空间保留。短暂故障恢复可复用 SDK 已验证的当前池，不为制造新对象而重开索引。
- LRU 和关闭在同一工作循环中等待原 SDK shutdown、后台任务退出及写者锁释放。前台工具和慢整理共存、取消、配置撤销及原情景 revision CAS 继续保留。
- SDK 后台模型请求回到 AstrBot，调用前后复核真实事件的会话、人格与学习权限，使用辅助调用计量。摘要公共入口另保留原生参与者和关系证据，避免被 SDK 默认空参与者参数覆盖。

本阶段只做接管相关的定向检查：旧库/图/向量留存、真实 SDK 所有权、写者锁释放、重开召回、模型空间切换、摘要/情景共享、整理期间前台读写、配置撤销、故障恢复及过时情景拒绝。没有再次跑整套回归。

## 通用更正、遗忘和撤销

Planner 现在提供 `correct_memory`、`forget_memory` 和 `undo_memory_change`。前两者只接受当前规划中实际查到或刚写入的原生段落 ID，后端还核对记录属于当前会话、人格的 `chat_summary`，并复用 SDK 对已删除、停用和受保护记录的检查。情景召回附带至多3条原始段落引用，召回数量为1时也能选具体段落，而不是改写情景标题。

- 每次操作须引用一个真实作者明确请求的原话，继续复核来源、学习和宿主权限。不会更改用户原文，也不操作人物账本或 LivingMemory 数据。
- 具体更正由 Planner 提供新段落和关系，转成 SDK 原生修正计划，再调用原执行、版本失效、图谱维护和回滚；没有再请求第二个模型重复生成同一具体计划。模糊反馈的原 SDK 规划器仍保留，后台消息桥尚待接入。
- 修正的来源证据按协程及实际计划 ID 绑定到公共 ingest，保留原请求作者、摘录及既有同文来源，不把依据写成虚构用户消息。
- 遗忘使用原删除日志与可恢复清理任务；撤销只接受同一请求作者在当前会话、人格中的原生操作。省略操作编号时，从原日志的近期记录中选择最近一条可撤销操作，重启后仍可继续，不把 SDK 内部回滚清理当作用户遗忘。
- 未配置嵌入服务时，SDK 恢复可以先恢复文字、将派生索引留在 `restore_pending`。工具分别返回原完成状态、`metadata_restored` 和 `pending_derived_indexes`，不会伪造全部完成；服务可用并经过原重试退避后，由相同原清理任务完成恢复。

本阶段只做三个定向场景的实际存储/原生工具循环检查：更正/回滚/遗忘/重开恢复和嵌入恢复后原任务完成；跨会话、伪造摘录及跨作者撤销拒绝；Planner 查询、更正、再次查询、回复器读取新记录和发送结果回流。模型与嵌入运输为受控响应，没有全量回归或线上消息验收。

## 动态消息与后台反馈桥

SDK 的消息接口现在读取获准的当前原生会话，不再把某次摘要的固定快照当作永久消息来源。结构化模式使用既有群聊底稿；原生模式读取 AstrBot 自己的 PlatformMessageHistory，按实际时间窗口分页，避免只读取最新一页而漏掉反馈窗口。没有另建完整聊天库。机器人输出、命令和被排除的学习作者按入口参数过滤；跨会话、人格变化或学习撤销时拒绝读取。

每个活动会话只保留无正文、附件和历史的原生授权身份及真实群/成员字段，用于后台权限复核和 SDK session 映射；不把它派发成用户消息，也不沿用旧管理员唤醒的临时白名单豁免。后台模型运输始终使用当前提供商、权限与辅助计量，即使后台任务在临时摘要上下文中重建也不会继承冻结的模型回调。

`memory_feedback_enabled` 默认开启，仍受记忆、应用、学习和会话权限控制。段落/关系查询使用原 `enqueue_feedback_task`，相同原生来源、查询及命中集合复用同一编号；原反馈分类、置信度门槛、失效过滤、关系维护及任务日志负责后续处理。沿用原12小时窗口及30分钟检查节奏；明确请求的即时更正仍由 Planner 工具完成。SDK 反馈策略通过作用域绑定读取开关，关闭或暂停学习后不会继续调用分类模型。

定向验收覆盖：实际查询去重、后来真实反馈进入原分类/应用链并使错误记忆退出召回；动态群聊底稿、命令排除、跨会话和暂停学习拒绝；实际 AstrBot SQLite 与 PlatformMessageHistoryManager 在多页数据中读取指定时间窗口。只替换外部模型运输，没有全量回归或生产消息验收。

## 验证范围

完整804项 Python 回归、随后新增的真实关系弱化/维护回归、Ruff 和真实发布包独立导入通过；前端未改动。来源验证逐个核对固定提交的原 Git blob、移植文件哈希和算法 AST，仅排除已记录的宿主导入及两个旧适配方法。新增修正事务位于自有子类，不修改移植的原算法。

这些是本地实际存储/内核验证；模型输出与嵌入运输采用受控响应。它们不替代真实模型语义质量、QQ 实聊和上线验收。
