# A_memorix SDK 内核移植与主链接管

对照仍固定为 MaiBot `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501`。本阶段加入 SDKMemoryKernel、运行时 facade、生命周期、检索执行、模型空间、纠错/回滚、删除/恢复、关系维护和导入管理等依赖；现在保留110个上游 Python 模块与6份原版语言模板。它们位于自有插件的 vendor 命名空间，第三方仓库不变。

## 已运行的内核能力

`NativeMemoryKernel` 继承实际 SDKMemoryKernel，使用原服务装配和 initialize/shutdown 生命周期。测试真实创建 SQLite、GraphStore 和 Faiss，持有数据目录写者锁，启动后台任务并在关闭时等待任务退出、持久化和释放锁；没有用替身模拟这些服务。

- 原 `ingest_text` 统一写入段落、实体、关系、幂等外部来源和派生任务。
- 原模型空间同步、双向量重建与 ready manifest 可实际运行；检索通过真实向量池找到无词面重叠的查询，同时拒绝其他会话的数据。
- 原删除预览、执行、清理任务和恢复可实际运行，删除后的数据不再进入检索，恢复后重新可读。
- 原修正预览、计划执行、失效版本过滤及回滚可实际运行。测试中的模型只提供受控计划，计划校验、存储变化、图谱更新和检索过滤均为原实现。
- 原同步工作边界一并移植：取消时等待真实文件工作结束，再释放生命周期资源，避免关闭后线程继续修改数据。

`sdk_host.py` 是显式的宿主边界：真实数据根目录、嵌入适配器、当前会话、消息快照和模型运输通过上下文绑定，不注册 MaiBot 的全局模块。嵌入向量的实际数量、维度和有限数值由原生适配器验证；只有已观察到的维度才声明 `source=observed`。该声明不改变既有模型指纹 hash，避免仅因增加验证信息而重复建立模型空间。

## 已修复的原版调用边界问题

实际修正曾稳定返回 `database is locked`：失效标记会更新图片关联和事实证据，但原辅助方法将提交交给调用方；随后图谱保存通过另一条连接写入同一数据库，被未结束的写事务阻塞。

`NativeCorrectionService` 只为单个目标的原失效更新补上受管事务，提交后再进入原图谱保存。原修正算法和第三方源码保持原样；真实执行、过滤与回滚回归通过。

## 接管尚未完成

**现有聊天主链仍使用 RoomMemory 适配；SDK 内核尚未接管它。本阶段没有部署，也不代表聊天中的通用纠错/遗忘已经生效。**

接下来必须完成这些主链工作，保持原对齐目标：

1. RoomState 交出存储所有权并绑定 NativeMemoryKernel；保留上一阶段前台记忆工具与后台模型共存、取消和重载的实际行为，不并行维护两套通用存储。
2. 将现有按会话/人格保存的 SQLite、图和模型空间接入 SDK 布局。原 SDK 使用 `vectors/active.json` 与 `vectors/spaces`，旧原生适配使用 `vectors/<fingerprint>/paragraphs|graph`；迁移应保留旧文件、已有事实和原文证据，验证后再切换。
3. 原生模型与消息绑定覆盖实际回调生命周期；后台调用继续复核宿主、会话、人格和学习权限，辅助用量真实计入统计。当前宿主模型配置回调桥已经能注册/解除，尚未接到 AstrBot 的真实提供商变更事件。
4. 实际接入 Planner/Replyer 查询、修正、遗忘及自动维护，并保持来源验证与操作范围；不能直接把无限制的 SDK 管理入口暴露给模型。
5. 继续人物近期/关系与通用检索贯通、LivingMemory 旧数据导入、图片/表情行动、直接唤醒统一规划和同模型完整文本对照。相关图片存储源码被依赖带入不等于图片理解或发送已经接通。

## 验证范围

完整804项 Python 回归、随后新增的真实关系弱化/维护回归、Ruff 和真实发布包独立导入通过；前端未改动。来源验证逐个核对固定提交的原 Git blob、移植文件哈希和算法 AST，仅排除已记录的宿主导入及两个旧适配方法。新增修正事务位于自有子类，不修改移植的原算法。
