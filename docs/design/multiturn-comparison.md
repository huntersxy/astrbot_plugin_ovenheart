# 正式多轮聊天对照：2026-10-26

本节点完成两组、共7轮合成人类输入的真实模型回放。烤箱之心使用真实 AstrBot 4.29.3 内核、插件加载器、消息流水线、Planner、正文生成和发送钩子；MaiBot 使用固定提交 `5c7637e6913c84d1c3d5e742fa9e95a7e70d3501` 的真实 Maisaka 运行时、调度器、推理循环、内置工具、回复器和历史维护。

平台发送使用回环接收器。没有连接 QQ、写入生产聊天历史或记忆，也没有修改 MaiBot、AstrBot 或其它第三方源码。原生侧运行的是已上线0.68.0的实现；本节点新增复现脚本与文档，没有修改聊天运行逻辑。

## 复现入口

- `scripts/native_chat_probe.py`：独立子进程启动真实 AstrBot，临时根目录复制目标插件，回环事件经原消息队列运行；不会启动管理服务或 QQ 适配器。
- `scripts/maibot_chat_probe.py`：先核对参考提交或完整源文件清单，在源仓库外建立新实例，运行真实 Maisaka。身份适配将原生人格逐字交给 Planner 的行为风格及回复器身份入口。
- 两个脚本从标准输入读取包含 `provider` 和 `persona` 的私有包；`provider` 包含匹配的原生提供商字段。报告只保存合成输入、可见回复、动作、用量或请求校验结果，不保存密钥、人格原文或内部推理。
- 原生入口接受 `--source`、`--cases`、`--case`、`--output`；参考入口另外要求 `--instance`，且该目录必须不存在、必须在参考源码外。参考环境依赖与单回复器对照相同。
- 本机受控运行器为仓库外 `.codex/tools/ovenheart-chat-parity-control-20261026.py`，复用既有生产运维认证，只把模型配置在进程标准输入中交给隔离实例。后续运行要重新确认环境与授权。

## 验收边界与暂停点

这次验证正式多轮文字主链，不是工坊示例，也不是完整复刻验收。参考侧没有平台发送账号，固定关闭引用装饰；两边没有严格冻结到相同时刻，参考输出上限在原生未声明时为4096，不能声称全部采样条件完全相同。不同系统的调度及工具目录也仍是各自真实实现。

尚未覆盖：真实 QQ 到达和回执、普通群聊中的自主参与时机、模型执行记忆查询/写入/更正的完整对照、长期人物一致性、带已学表达的效果、媒体理解与发送，以及多人持续插话。特别是本轮 `wait` 记录不能代替新输入中断与接续的真实模型对照。

用户在本节点运行中要求“做完当前节点先暂停”。完成归档、提交及当前节点发布核验后暂停整体目标；下次从上述剩余项接续，不重复旧记忆迁移。当前会话的额度接口没有提供有效百分比，未沿用旧聊天的历史余额；保留10%的要求仍有效，恢复时需重新确认可用额度。

## 恢复后的记忆生命周期节点

用户随后明确“继续”。在同模型、同人格、回环发送与全新临时存储条件下，开启真实原生记忆，新增 `scripts/chat_memory_cases.json` 的八轮合成输入：记住约定、查询、更正、另一成员查询、遗忘、查询库状态、撤销、另一成员再查询。自动学习、插件增量摘要及嵌入关闭，SDK自身情景后台仍真实运行。脚本用 `--memory` 启用此条件，并保存每轮实际工具结果和只读有效段落列表。

初次完整回放发现真实功能故障：段落更正已生效，但情景仍包含旧版；遗忘新版后后台旧情景再次出现。下一轮模型沿用之前的遗忘请求删除旧版，撤销随之针对错误操作。修复后重跑八轮，写入、更正、遗忘和撤销均作用于正确版本；有效列表数量依次为1、1、1、1、0、0、1、1，第六轮只执行查询，最后一轮召回的段落及情景证据均指向更正版。

恢复工具的状态说明又经一次八轮复测：共39次实际模型运输（27次Planner、8次正文、4次SDK后台），每轮完成发送且无流水线错误。撤销后模型先查询，确认恢复的是周日下午四点、云桥咖啡店的约定；派生索引仍由原SDK报告为未完成，不能声称全部修复。当前样本仍把 `success=false` 字段原样说给了用户，表达层有改进空间，未将这一点标记为完成。
