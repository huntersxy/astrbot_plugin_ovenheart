# 0.66 社交回复：参与动机、记忆和表达选择

本轮实现针对[拟人感差距调查](../maibot-humanlikeness-audit-20261025.md)中已经观察到的选择器超时、前置等待和参与意图不足。它补齐真实聊天链路中的信息与动作，不引入好感度数值、虚构生活事件或新的记忆数据库。

## 回复前的实际流程

启用 Jev 且使用 contextual 检索时：

1. 从生效习惯中召回候选，向量等待最多1.5秒；保留已有的相近表达去重、例句和近期曝光参考。
2. 一次 Jev 请求测量最多12条候选的情境适用性；直接回复同时判断回应动作和篇幅，自主参与已有表达意图时复用。
3. 只纳入达到适用门槛的真实条目 ID，也允许一条不选。跳过原本串行的重排序与聊天模型选择请求。
4. Jev 暂不可用时，把最多四条生效的表达作为明确标注的可选候选交给主回复模型。主模型结合完整上下文决定是否采用，不再增加聊天筛选请求，也不将候选记作已验证的 selected_ids。当前输入直接命中的词义仍有独立路径。

辅助判读最多4秒，组装层保留总等待上限。这里的时间预算不包含主回复生成、原生记忆检索、排队与平台发送，不能宣称整轮回复能在这些时间内完成。未启用 Jev 时继续使用原有情境选择器及其配置。

人工底稿、宿主人格和请求权限仍由原流程管理。代码不改写用户设定的宿主人格，也不假设“句子越短越拟人”。新提示允许有依据的观点、分歧、倾听和自然口语变化；明确任务仍完整完成。

## 参与决定不再只给一个通用目标

原来的同一次 Jev 参与请求，在选择真实目标 / wait / observe 之外，还判断：

- 回应动作：直接回答、参与话题、接梗调侃、陪伴倾听、表达不同意见、澄清、简短接住、修正自己的话。
- 本轮篇幅：短促口语、自然展开、完整任务。

低把握的风格选项不强加给回复模型。参与决定通过之后，实际目标原文、引用、自己的近话和具体动作一起进入表达选择与主回复。动作不授予工具权限，也不是预制台词。明确唤醒照常绕过参与门槛。

## LivingMemory 的运行时扩展

Jev 参与判断现在可通过现有 MemoryBridge 读取最多三条获准访问的回忆，单独短等待最多1.5秒。保留已存在的参与者、关键事实和来源时间字段；参与者 ID 与当前消息使用一致的临时成员别名。查询关联的 sequence 不代表旧事实属于该消息作者。

读取遵守 LivingMemory 原生会话开关、访问控制、实例、作用域及人格过滤，并保留检索后复核。目标尚未确定时跳过个人作用域；不把触发新消息的成员冒充为最终回复对象。最终回复的实际来源绑定及原生召回 / 反思照常运行。

原生召回 hook 返回之后，只有它确实追加了 `<RAG-Faiss-Memory>` 片段，且当前群聊允许烤箱之心应用时，才补充一段临时的社交记忆说明：

- 根据真实参与者和时间延续熟悉程度、共同话题、承诺或此前分歧。
- 不背诵档案，不从同群旧事推断当前成员的经历，不凭空套用亲密关系。
- 当前意愿、更正优先于旧印象，无关回忆忽略。

该扩展不额外查询，不改原记忆内容或反思结果，不存进宿主历史。既有卸载恢复机制仍负责撤销所属 hook；第三方源码、版本、配置和数据库格式均不需要改动。

## 多人交错的续接

刚回复的成员在120秒内首次继续说话，仍可获得一次越过最少新消息与冷却的判断机会，中间夹有其他成员发言不再直接失去机会。仅判断并回应这个继续说话的人；不是把窗口里其他人也全部回复。

这次续接的固定静默收集最多2秒，普通自主参与继续遵守原配置。仍保留一次机会、实际小时额度、直接唤醒优先、作用域、过期和最终投递检查；致谢、告别或已完成话题仍可旁观。

## 验证记录

- 最终完整 Python 回归：733项通过；覆盖参与者别名、最小预算、原生请求、记忆 hook、权限、流式回复、媒体和学习链路。Ruff、JavaScript语法和安装包校验通过。测试使用本机AstrBot 4.29.1 SDK；宿主工作区另有独立修改，未纳入本次提交，未另行验证干净上游副本。
- 使用现有真实 Jev 接口执行六个公开合成场景：倾诉、朋友调侃、纠正自己、完整操作任务、拒绝亲昵称呼、简单计算。期望回应动作、必要/不适用习惯和任务篇幅检查全部通过。
- 六次辅助调用为0.316、0.292、0.339、0.294、0.321、0.301秒。仅是这一批小样本的辅助判断时间，不是整体延迟，也不是相对旧流程的受控性能基准。
- 测试只发送脚本内的合成输入，没有真实聊天原文、QQ消息或生产学习批次，没有部署代码或修改生产配置。

可从源码目录运行合成验证，配置路径应指向自己的受保护配置文件；脚本只读配置，不输出密钥：

```powershell
python scripts/evaluate_social_reply.py --config <受保护的插件配置文件路径>
```

这些验证证明结构化判断、权限归属和原生链路能衔接，不证明生成出的完整回复已经与 MaiBot 同等自然。上线后的真实聊天观察和同模型、同上下文的人评仍是下一阶段的效果证据。
