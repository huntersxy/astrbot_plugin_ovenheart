# 语义分段与发送节奏

移植固定 MaiBot 的完整 `llm_sentence_splitter.py`，仅替换日志及模型运输导入；另移植原分段压缩与打字时间函数。源文件、移植文件及符号 AST 哈希见 `vendor/maibot/response_source.json`，可由 `scripts/port_response.py` 重现。宿主绑定使用作用域 ContextVar，不注册全局 MaiBot 模块。

`reply_rhythm_enabled` 默认开启，对本插件 Planner 的非流式原生发送生效。正文达到40字时由 `reply_split_provider_id` 指定的模型判断语义切分位置，留空使用 Planner 或当前会话模型。沿用原结构校验、宽松标点/空白比较、原文位置映射和段尾分隔符处理；发送的是原文片段，模型改写或返回失败时回退原文。使用原压缩规则合并到 `reply_split_max_messages` 段，默认3。调用受 Planner 超时限制并计入 `reply_split` 辅助用量。

发送适配只处理一段正文及其原生引用/提及头；混合媒体和特殊消息链保留原平台处理。引用和提及只随第一段发送，后续段不重复。宿主 `segmented_reply.enable` 已开启时沿用宿主分段，避免二次拆分和双倍等待；没有改全局平台设置。流式与未进入 Planner 的原生路径保持原宿主策略。

段间打字时间按原中英文与图片规则计算，使用 `reply_typing_speed` 倍率，默认0.25；0关闭等待。原生适配对单段等待封顶5秒，避免长任务输出因模拟打字而额外等待很久。图片/纯表情使用原图片规则；每次等待后复核当前实际参与条件，再交给原发送器。自己媒体仍由同一事件的实际发送观察器记录。

实际成功的文字段保留在当前发送回执中。若后续原生适配器失败，Planner 与自身上下文只使用已成功片段，标记 `partial_text`；完全未观察到成功段时返回 `delivery_failed` 并释放预留。部分发送不把该目标的任务标记完成，直接请求可继续发送尚未完成的内容，重新收集原生请求，避免零群聊频率阻断明确任务。回执与平台最终确认仍分开表述。AstrBot 自己保存的模型生成历史遵循其原契约，本插件没有把未发送片段伪装为已发送的自身观察。

三个定向场景覆盖原生真实消息链中的正常分段、第二段失败及模型篡改回退，并核对原文、首段引用/提及、实际回执和辅助计量。只替换模型与平台发送运输，未做真实模型断句质量或 QQ 回执验收，未重复全量回归。
