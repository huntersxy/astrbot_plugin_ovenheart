# 使用指南

## 配置模型

所有提供商先在 AstrBot 中创建，工坊只填写提供商 ID，不保存额外密钥。

| 配置 | 用途 | 留空时 |
| --- | --- | --- |
| 学习模型 | 提取和审核习惯 | 使用当前聊天模型 |
| 决策模型 | 选择回复对象、查询和等待 | 使用学习模型或当前聊天模型 |
| 文字向量模型 | 语义召回习惯、记忆和图谱 | 使用文字相关性与稀疏检索 |
| 图片嵌入模型 | 相似图片检索 | 支持同图记忆 |
| 记忆整理、人物提取模型 | 提取有来源的经历和人物事实 | 使用学习模型或当前聊天模型 |

图片嵌入需要支持图片输入的模型。文本嵌入、图片嵌入和视觉聊天是不同用途，不应填成同一个不支持图片的提供商。图片嵌入支持 AstrBot 的 DashScope 多模态提供商，以及硅基流动的 Qwen3-VL-Embedding。

## 学习与表达

在“设置 → 学习与生效”选择指定成员、黑名单和会话范围。机器人自己的回复只帮助理解语境，不作为人类语言证据。

“学习库”展示习惯内容、适用情境、原文和自检结果。批准后才会参与回复检索；没有合适习惯时允许不选。可以编辑、停用或删除，不需要为每次聊天添加规则。

人格底稿与 AstrBot 人格共同约束表达。当前用户对长度、称呼和语气的明确要求优先于学到的习惯。

## 表情

表情是独立的顶层页面，包含“图库”“上传与导入”“选择与发送”。初次使用可以按以下流程配置：

1. 在“上传与导入”添加 PNG、JPEG、WebP 或 GIF，填写含义与使用场景。单图不超过 10 MB。也可以选择已有 `meme_manager` 表情包，分批导入原图和已有描述；源素材保持原样，相同图片按内容去重，导入可暂停。
2. 在“图库”检查素材并修正描述。“公共图库”供所有获准使用表情的会话选择；“本会话候选”只显示当前会话内已识别的表情，普通照片不会自动作为候选。
3. 在“选择与发送”开启“Planner 表情动作”。通用记忆、图片记忆及记忆辅助也须开启，可在记忆设置中检查。默认由 Planner 阅读最多六张候选的描述，选择随文字附图或单独发送；不追加情感模型调用。正文先发送。

候选拼图默认关闭。开启后需要支持图片的 Planner，会增加图片输入。没有提供候选序号的单独表情动作会使用视觉选择器，可填写独立视觉模型 ID；留空沿用规划或宿主图片描述模型。该路径增加一次选择调用，失败会报告实际状态。

烤箱之心为自己的 Planner 回复统一负责表情，运行时适配会跳过 `meme_manager` 的重复情感检索和自动附图。其他原生会话仍遵循该插件自己的配置；不修改其源码、图库或配置。完成素材导入并确认自有表情可用后，可在 AstrBot 中停用 `meme_manager`，烤箱之心的公共图库不依赖它运行。

原生 Planner 回复的表达候选直接交给正文模型判断，避免在规划后再调用一次独立情境筛选；候选不表示已经采用，模型可以全部不用。

## 分段回复

初次安装无需另配断句模型。在“设置 → 表达与检索”保持“分段回复与发送节奏”开启、“断句方式”为“本地规则”即可，默认最多发送 3 条。规则模式复用 AstrBot 的分段词并支持换行，无额外模型调用；可在 AstrBot 的分段词设置中调整断句位置。超出条数上限的片段合并发送，不截断正文。

例如“先保存好。再继续。”可以分成两条；首段立即发送，后续段落按长度等待。模拟打字倍率默认 0.25，设为 0 可取消所有段间等待。

需要模型判断更细的语义边界时，再将断句方式切为“模型语义”，并填写 AstrBot 已配置的快速聊天模型 ID。留空使用 Planner 或当前会话模型。每条回复会增加一次断句调用，默认最多等待 3 秒；失败或超时直接使用本地规则结果，可在用量中查看“语义断句”。

普通模型回复与 Planner 正文均支持分段。代码、列表、包含括号或引号的正文保持整条发送；流式输出、图文混排和插件命令回复沿用原发送方式。若 AstrBot 自身已开启分段，本插件直接交由宿主处理，段数与间隔以宿主设置为准。

## 群聊参与

“关闭”保留明确唤醒后的回复；“仅观察”记录参与判断；“自动参与”允许按配置参与群聊。名字唤醒单独开启。

持续规划器根据真实消息选择对象，回复后接收实际结果，再决定继续、等待或停止。已完成的目标不会重复回答；部分发送失败会保留尚未完成的请求。

自主工具名单只缩小可用范围。实际工具仍由 AstrBot 会话、人格和权限决定。

## 记忆

记忆按真实会话和人格隔离，人物资料还按成员身份区分。明确更正会替换相应事实；冲突与不确定信息不会直接变成确定的长期了解。

在聊天中可以明确要求记住、更正或遗忘。系统只有完成对应写入后才能确认；索引仍待处理时会报告实际状态。

记忆控制台支持记录、人物、图片、关系图谱、时间线、来源、检修和删除管理。导入支持文字、TXT、Markdown 及 `.amembundle` 记忆包；面板文件上限为 16 MB。删除前可预览影响范围。

记忆管理的“导入与来源”提供 LivingMemory 快捷导入：读取同一 AstrBot 数据目录中的文本记忆，选择来源会话与人格，导入到当前选中的会话与人格。无需启用 LivingMemory；保留原始来源，重复导入自动跳过，支持分批暂停。不复制源向量、索引或插件配置。聊天、学习与判读统一使用烤箱之心自己的原生记忆。

## 数据与资源

配置由 AstrBot 管理。学习与记忆写入 `data/plugin_data/astrbot_plugin_ovenheart/`，不写入插件源码目录。

原始学习素材默认保留 14 天，每个会话最多 300 条；习惯和记忆有各自的管理操作。学习和整理会把相关片段发给配置的模型服务。

记忆内核按需加载，默认最多驻留 4 个会话；未创建记忆数据库的会话进行空查询时不启动内核。嵌入使用 AstrBot 已有提供商，服务器无需加载本地嵌入模型。

## 排查

- **习惯没有影响回复**：检查应用开关、审核状态、学习范围，以及本轮检索记录；模型可以不选不合情境的习惯。
- **没有主动接话**：检查参与模式、频率、每小时限额、会话权限和工具名单。
- **记忆暂不可用**：检查提供商 ID、网络、模型维度和日志中的实际等待位置。暂时降级不代表记录被删除。
- **页面打不开**：确认 AstrBot 插件已启用，刷新插件卡片中的工坊页面，并检查浏览器和宿主日志。

开启 Debug 会记录聊天和注入内容，排查完成后关闭；共享日志前先脱敏。
