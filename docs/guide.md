# 使用指南

## 不确定怎么选

初次使用保持以下推荐值即可。原生插件配置页和人格工坊显示相同的中文选项。

| 设置 | 推荐选择 | 什么时候需要换 |
| --- | --- | --- |
| 新习惯如何生效 | 高置信度自动生效（`auto`） | 希望逐条确认时切换为先审核后生效（`review`）。入库自检默认开启，存疑或低置信度结果仍待审核。 |
| 是否自主参与群聊 | 自动参与（`auto`） | 需要检查时机时选仅观察（`observe`），只希望明确唤醒后回复时选关闭（`off`）。已有安装保留保存过的设置。 |
| 群聊历史由谁管理 | AstrBot 管理（`native`） | AstrBot 管理会增强宿主原生群聊上下文；选择烤箱之心管理（`structured`）时，先关闭 AstrBot 的群聊上下文感知与原生主动回复。 |
| 如何让模型使用人格与习惯 | 默认投递（`cached`） | 模型明显不按人设说话时可尝试双重投递（`dual`），但输入更长；系统投递（`system`）仅用于有特殊接口要求的情况。 |
| 已学表达的选择方式 | 结合当前对话（`contextual`） | 已配向量模型、只需按含义查找时可选按意思匹配（`hybrid`）；希望少用资源、不配置向量模型时选按字词匹配（`lexical`）。 |

## 浏览与筛选

选择 `structured` 后，烤箱之心会把群成员、引用、媒体和机器人自己的已发送消息放进同一条群聊时间线，规划器与最终回复共用这条时间线。它以基准条数保留最近历史，最多向模型提供两倍基准；超过两倍时裁回基准，并保留 AstrBot 原生对话作为可切回 `native` 的历史记录。

工坊各页独立管理展示范围，不再使用顶部的统一会话选择器。学习库、学习与参与、记忆和表情默认汇总全部来源；自画像按人格列出，不重复展示使用同一人格的群聊。需要缩小范围时展开本页筛选，选择人格、会话、类型或状态；记忆和表情支持一键重置筛选。

管理页的汇总浏览不改变聊天中的记忆隔离。记录保留来源，编辑直接使用所选记录的归属；导入文字、记忆包或新建关系时，在对应表单选择保存目标。清理原始素材的目标只在「设置 → 素材维护」选择。

## 配置模型

所有提供商先在 AstrBot 中创建并启用，再到“设置 → 模型分工”按任务选择。原生插件配置页同样提供模型选择器。工坊复用 AstrBot 的模型与认证，不保存额外密钥。

| 配置 | 用途 | 留空时 |
| --- | --- | --- |
| 最终回复 · Replyer | 生成真正发出的正文及原生工具调用 | 始终跟随 AstrBot 当前会话的模型与生成设置，无需另配 |
| 聊天规划 · Planner | 选择回复对象、查询、等待和结束，需支持工具调用 | 使用 AstrBot 当前会话模型 |
| 表达与习惯学习 | 从聊天提取表达、性格倾向、词汇与行为习惯 | 使用 AstrBot 当前会话模型 |
| 学习入库自检 | 独立核对候选与原文证据 | 使用 AstrBot 当前会话模型 |
| 表达情境筛选 | 独立筛选当前对话适合的表达 | 使用 AstrBot 当前会话模型 |
| 记忆整理 | 聊天回想压缩、增量摘要、情景整理与反馈维护 | 使用 AstrBot 当前会话模型 |
| 人物事实与画像 | 从本人原文提取事实和更正 | 使用 AstrBot 当前会话模型 |
| 记忆主动复核 | 检查旧记忆，提出有依据的修正建议 | 使用 AstrBot 当前会话模型 |
| 语义断句 | 仅模型语义断句启用时调用 | 使用 AstrBot 当前会话模型；本地规则模式不调用 |
| 表情视觉选择 | 可选，需要支持图片输入 | 使用 AstrBot 图片描述模型 |
| 文字向量模型 | 语义召回习惯、记忆和图谱 | 使用文字相关性与稀疏检索 |
| 图片嵌入模型 | 相似图片检索 | 支持同图记忆 |

各项模型配置独立，留空不会借用学习或 Planner 模型。持续 Planner 已选定表达时，正文沿用这次选择，不额外调用情境筛选模型；Jev 联动仍使用 Jev 连接中的模型设置。已保存的旧模型 ID 保留，更新不会修改 AstrBot 的会话选模。

图片嵌入需要支持图片输入的模型。文本嵌入、图片嵌入和视觉聊天是不同用途，不应填成同一个不支持图片的提供商。图片嵌入支持 AstrBot 的 DashScope 多模态提供商，以及硅基流动的 Qwen3-VL-Embedding。

## 学习与表达

在“设置 → 学习与生效”选择指定成员、黑名单和会话范围。机器人自己的回复只帮助理解语境，不作为人类语言证据。

“学习库”默认显示全部状态的习惯，展示内容、适用情境、原文和自检结果。新习惯默认在通过自检且置信度达到门槛后自动参与回复检索；其余保留待审，也可切换为全部先审后用。没有合适习惯时允许不选。可以编辑、停用或删除，不需要为每次聊天添加规则。

Planner 返回候选之外的表达 ID 时，只保留本轮真实候选中的条目；全部无效则按未选表达继续回复，不再为此调用模型重选。平台原始消息 ID 只有唯一匹配当前真实人类消息时才映射为序号。

人格底稿与 AstrBot 人格共同约束表达。当前用户对长度、称呼和语气的明确要求优先于学到的习惯。

规划与正文使用同一套相处准则：先按人格和真实语境形成态度，再选择回应动作；同一话题衔接此前实际说过的话，有新信息时自然调整。闲聊允许短回应、接梗或不同意见，不固定附加建议和追问；亲疏变化须有真实互动依据。

普通短句按完整语义连续书写，不将词语或其后的标点拆到下一行；正常段落、列表、代码及明确要求的排版保留。流式片段按原文连接，不因片段边界增加换行。

## 表情

表情是独立的顶层页面，包含“图库”“上传与导入”“选择与发送”。初次使用可以按以下流程配置：

1. 在“上传与导入”添加 PNG、JPEG、WebP 或 GIF，填写含义与使用场景。单图不超过 10 MB。也可以选择已有 `meme_manager` 表情包，分批导入原图和已有描述；源素材保持原样，相同图片按内容去重，导入可暂停。
2. 在“图库”检查素材并修正描述。“公共图库”供所有获准使用表情的会话选择；“本会话候选”只显示当前会话内已识别的表情，普通照片不会自动作为候选。
3. 在“选择与发送”开启“Planner 表情动作”。通用记忆、图片记忆及记忆辅助也须开启，可在记忆设置中检查。默认由 Planner 阅读最多六张候选的描述，选择随文字附图或单独发送；不追加情感模型调用。文字和图片属于同一轮回复；附图时正文先发送，只要表情时可以直接发图。

选图按机器人本轮准备表达的用途、动作和对象关系查找全库，不再只从最近上传的图片里抽取。配置文字向量模型后会同时按含义匹配，描述向量在现有数据库中分批缓存；未配置或超时则按字词匹配。规划模型选择最终图片，候选不合适时可以继续换用途查找或不发送；视觉选择器返回错误、缺少或越界编号时不会用第一张替代。近期发过的图片会适度降权。

在“选择与发送”可开启 **静态图转 GIF 发送**，默认关闭。开启后，烤箱之心托管回复中的静态图片转换为 1 帧 GIF，透明区域保留；原有 GIF 和其他动态图保持原样。转换只影响发送编码，不修改图库原文件，也不另存临时 GIF。

候选拼图默认关闭。开启后需要支持图片的 Planner，会增加图片输入。没有提供候选序号的单独表情动作会使用视觉选择器，可在“设置 → 模型分工”选择独立视觉模型；留空沿用 AstrBot 图片描述模型。该路径增加一次选择调用，失败会报告实际状态。

烤箱之心为自己的 Planner 回复统一负责表情，运行时适配会跳过 `meme_manager` 的重复情感检索和自动附图。其他原生会话仍遵循该插件自己的配置；不修改其源码、图库或配置。完成素材导入并确认自有表情可用后，可在 AstrBot 中停用 `meme_manager`，烤箱之心的公共图库不依赖它运行。

原生 Planner 回复的表达候选直接交给正文模型判断，避免在规划后再调用一次独立情境筛选；候选不表示已经采用，模型可以全部不用。

## 分段回复

初次安装无需另配断句模型。在“设置 → 表达与检索”保持“分段回复与发送节奏”开启、“断句方式”为“本地规则”即可，默认最多发送 3 条。规则模式复用 AstrBot 的分段词并支持换行，无额外模型调用；可在 AstrBot 的分段词设置中调整断句位置。超出条数上限的片段合并发送，不截断正文。QQ 官方机器人会自动把单次回复上限收紧为 3 条，其他平台沿用配置。

例如“先保存好。再继续。”可以分成两条；首段立即发送，后续段落按长度等待。模拟打字倍率默认 0.25，设为 0 可取消所有段间等待。

需要模型判断更细的语义边界时，再将断句方式切为“模型语义”，并在“设置 → 模型分工”选择语义断句模型。留空使用 AstrBot 当前会话模型。每条回复会增加一次断句调用，默认最多等待 3 秒；失败或超时直接使用本地规则结果，可在用量中查看“语义断句”。

普通模型回复与 Planner 正文均支持分段。代码块和列表保持整条发送；颜文字、括号、引号及行内代码内部不切分，外面的句子和换行仍可分段；流式输出、图文混排和插件命令回复沿用原发送方式。若 AstrBot 自身已开启分段，本插件直接交由宿主处理，段数与间隔以宿主设置为准。

Oven Multi 的分段回复同时开启时，由其统一处理分段和间隔；烤箱之心继续检查本轮回复目标，不重复拆分。

两者联动时，剩余段落发完后才记录回复完成、移除思考表情。自我上下文、学习语境与 Planner 回执使用实际成功发送的段落；中途失败或取消时保留已发送内容，不把未发出的后文当成已经说过。

Oven Multi 的文件检索和梗百科预查使用烤箱之心选定的实际回复目标；目标只有图片而没有文字时，不借用较新的其他成员消息检索。Jev 辅助判读遵守 Oven Multi 的会话启停、插件白名单和自身黑名单，未配置密钥时跳过。

## 群聊参与

默认“自动参与”，按配置的频率与当前语境加入群聊；“仅观察”记录参与判断；“关闭”保留明确唤醒后的回复。名字唤醒单独开启。修改安装默认值不会覆盖已有配置。

持续规划器根据真实消息选择对象，回复后接收实际结果，再决定继续、等待或停止。已完成的目标不会重复回答；部分发送失败会保留尚未完成的请求。

自主工具名单只缩小可用范围。实际工具仍由 AstrBot 会话、人格和权限决定。

### 提及群成员与其他机器人

可直接要求“@幽幽子，然后发 /今日猪猪”。正文模型先用 `ovenheart_find_group_members` 按群名片、昵称或账号查找当前群真实成员，再用 `ovenheart_mention_group_members` 安排本轮提及；实际发送为真实 @ 组件与正文组成的同一条消息，指定对象不会被改回提问者。支持同时提及多位成员，流式和分段回复只在开头提及一次。普通回复继续沿用原来的收件人绑定。QQ 官方机器人使用 OpenID，平台没有 OneBot 群成员列表接口，因此会自动隐藏这两个需要成员目录核验的工具；当前消息中的已知发送者仍可被直接提及，旧消息目标不会被强行当作官方引用。

同名时先确认对象，不猜账号；成员目录暂不可用时报告实际错误。安排提及不代表已经发送，发送了指令也不代表另一个机器人一定执行成功。仅单独 @ 而不带正文时，可使用宿主已开放的 `send_message_to_user` 的 `mention_user` 组件。

这两个工具遵循 AstrBot 人格的工具权限。使用自定义工具名单时需加入它们；自动参与时还须符合烤箱之心的自主工具名单。成员目录仅按需查询，保留群名片与昵称，不将整群成员列表写入学习或记忆库。

## 记忆

记忆按真实会话和人格隔离，人物资料还按成员身份区分。明确更正会替换相应事实；冲突与不确定信息不会直接变成确定的长期了解。

在聊天中可以明确要求记住、更正或遗忘。系统只有完成对应写入后才能确认；索引仍待处理时会报告实际状态。

明确说明或更正图片中的角色、物件时，规划器可在已有 `remember_memory` 中附带真实图片消息的证据，将说明与原图关联。只有获准的当前会话图片、真实原话和已入库的图片记录可以建立关联；多图指代不明时需先澄清。再次查询同图时优先复用已有描述，并补充原图出现后三分钟内仍保留的同一发件人原话（每次出现最多四条）。附近发言仅为语境，不能自动视为已确认的图片身份；历史素材过期后不保证还能恢复这些原话。

记忆控制台支持记录、人物、图片、关系图谱、时间线、来源、检修和删除管理。导入支持文字、TXT、Markdown 及 `.amembundle` 记忆包；面板文件上限为 16 MB。删除前可预览影响范围。

记忆管理的“导入与来源”提供 LivingMemory 快捷导入：读取同一 AstrBot 数据目录中的文本记忆，选择来源会话与人格，导入到当前选中的会话与人格。无需启用 LivingMemory；保留原始来源，重复导入自动跳过，支持分批暂停。不复制源向量、索引或插件配置。聊天、学习与判读统一使用烤箱之心自己的原生记忆。

## 数据与资源

配置由 AstrBot 管理。学习与记忆写入 `data/plugin_data/astrbot_plugin_ovenheart/`，不写入插件源码目录。

原始学习素材默认保留 14 天，每个会话最多 300 条；习惯和记忆有各自的管理操作。学习和整理会把相关片段发给配置的模型服务。

记忆内核按需加载，默认最多驻留 4 个会话；未创建记忆数据库的会话进行空查询时不启动内核。嵌入使用 AstrBot 已有提供商，服务器无需加载本地嵌入模型。

学习主库复用一个专用线程内的写连接，每次操作仍独立提交或回滚；只读查询使用独立短连接。插件卸载时等待写入结束并关闭连接。连接策略及本地对比见[数据库连接评估](database-connections.md)。

## 排查

- **习惯没有影响回复**：检查应用开关、审核状态、学习范围，以及本轮检索记录；模型可以不选不合情境的习惯。
- **没有主动接话**：检查参与模式、频率、每小时限额、会话权限和工具名单。
- **记忆暂不可用**：检查提供商 ID、网络、模型维度和日志中的实际等待位置。暂时降级不代表记录被删除。
- **页面打不开**：确认 AstrBot 插件已启用，刷新插件卡片中的工坊页面，并检查浏览器和宿主日志。

开启 Debug 会记录聊天和注入内容，排查完成后关闭；共享日志前先脱敏。

## 记忆范围与主动复核

在「记忆 → 记忆设置 → 通用与图片」保留“按会话隔离记忆”（推荐），各会话分别积累资料。关闭后，同一 AstrBot 人格在所有会话共享记忆，包括私聊与群聊；人物仍按真实账号识别，不同人格分开。隔离开关只控制召回范围：关闭后自动包含同一人格各会话已积累的资料，开启后只召回当前会话。记录始终保留真实来源，不搬移或清空，也不改变聊天历史或习惯的作用范围。

“经历与人物”中的主动复核默认开启：全插件每 3600 秒最多一轮，各记忆库轮流检查，每轮最多两条最久未复核或与新记录有关的记忆。没有足够资料时不调用模型；暂停学习或关闭主动复核后停止。年代久不是删除理由，新原文明确更正了同一事实、且模型把握足够时才自动执行。

在「记忆检修 → 修正历史」展开记录，可查看建议的新内容、真实来源与原文证据。待确认的有效建议可手动确认；已执行的修正可回滚。后台复核计入辅助模型用量，间隔越短调用机会越多。

## 人格自画像

打开侧栏「自画像」，顶部选择一个实际会话，页面会显示它使用的 AstrBot 人格。填写简明的外观特征，按需上传一张静态 PNG、JPG 或 WebP 图片（不超过 2 MB 和 419 万像素），点击保存。同一人格在不同会话使用同一份自画像，不受记忆隔离开关影响。

文字聊天只提供外观描述；收到图片、且该会话回复模型在 AstrBot 声明支持识图时，额外提供自画像作对照。资料作为本轮临时上下文，不替换人格身份、不写入聊天历史，不另外调用模型生成或识别自画像。只描述外观有助于避免把来图人物的经历误认成自己。需要替换形象时重新上传并保存，清除按钮同时移除图片与描述。

普通聊天中，当前会话的文字与媒体配文统一从正文发送，按所选分段规则处理。发送工具保留独立媒体、跨会话通知和定时任务用途，避免先用工具发一句、再追加“已回复”的执行汇报。
